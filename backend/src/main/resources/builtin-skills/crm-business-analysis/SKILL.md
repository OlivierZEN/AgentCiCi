# CRM 经营分析

## 触发范围

当用户询问哪些产品销量最好、卖得最多、销售额最高、最热销，或要求按订单数、客户数比较产品时使用本技能。

## 必须遵循

1. 必须调用 `crm_product_sales_rank`，禁止自行串联原子 CRM/MCP 工具并在模型侧计算排行。
2. “销量最好、卖得最多、出货量最高”使用 `SALES_QUANTITY`。
3. “销售额最高、收入最高”使用 `SALES_AMOUNT`。
4. “订单最多、订单数最多”使用 `ORDER_COUNT`；“客户覆盖最多、购买客户最多”使用 `CUSTOMER_COUNT`。
5. 未明确指标的“销售得比较好、热销”使用 `SALES_AMOUNT`，并在回答中说明口径。
6. 未明确时间时使用最近 30 天；明确的近 N 天、本月、上月、本季度或起止日期必须原样落实到工具日期参数。
7. 未明确数量时返回 Top 5；中文或阿拉伯数字明确的 Top N 必须完整解析且只接受 1 到 20。同一问题出现多个不同指标、最少/最低/升序等非降序意图、不一致时间范围、越界 Top N 或其他无法可靠解析的表达时，不得静默选择第一个值或改成默认值，应先请用户澄清。
8. 事实、贡献率、实现均价、客户集中度和前瞻信号全部使用工具的确定性结果；不在模型侧重算、改写或补造数值。
9. `EMPTY` 仅表示核心对象可见且统计期确无有效销售。`DATA_ACCESS_INCOMPLETE` 必须明确为权限或关联可见性不完整，不得声称“没有销售”。
10. `PARTIAL` 保留可验证的订单销售排行，只说明商机、合同或客户增强的缺失范围。`DATA_QUALITY_BLOCKED` 不输出伪排行。
11. 不向用户展示原始 JSON、内部工具名、产品内部 ID、owner ID、调用参数或技术 fallback 文案。
12. 订单销售额是经营口径，不称会计收入；无成本数据时不推断毛利或利润。

## 回答格式

1. 直接结论：统计期、销量冠军、订单销售额冠军与一句总体判断。
2. Top N：排名、产品、销量/单位、订单销售额、贡献率、增长、订单数和客户数。
3. 经营诊断：量价、客户覆盖与集中度，每条必须携带事实依据。
4. 前瞻信号：开放商机产品、最近预计签约日期、活跃/临期合同和续约缺口；不混入已实现销售。
5. 建议动作与口径覆盖：动作具体到产品、客户、商机或合同；披露有效状态、退货、币种、数据截止时间与扫描/计入数。
