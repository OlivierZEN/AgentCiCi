# AgentCiCi 项目总览

更新时间：2026-04-16  
适用项目：`cc-cici-assistant`

## 1. 项目是什么

`AgentCiCi` 是一个面向企业场景的多组织智能体运行与治理平台，目标不是只做一个聊天窗口，而是逐步形成一套可管理、可扩展、可审计的企业 AI 工作台。它是独立产品品牌，CloudCC、Salesforce、企业微信、飞书等是外部系统、CRM 或渠道集成。

当前产品包含两条主线：

- **助手端**：面向员工，提供聊天、RAG 知识增强、工具协同和后续的 Agent 使用能力。
- **管理端**：面向组织管理员，负责知识库、模型、工具、运维和用户管理。

平台的核心约束是：

- 所有租户敏感数据路径都必须带 `org_id`
- 权限按 `ORG_ADMIN` / `ORG_USER` 区分
- 模型、知识库、工具与审计都要围绕多组织隔离展开

## 2. 当前核心方向

项目当前最高优先级已经收敛到 **Agent Builder**，它的目标不是拖拽节点，而是：

**自然语言 Spec -> AI 编译生成 workflow code / manifest / preview graph -> 服务端托管执行与治理**

这意味着：

- 自然语言 Spec 是用户主输入
- 生成的 workflow code 才是执行载体
- 流程图只是只读预览，不是人工编辑入口
- 后端负责执行、权限、安全、审计、版本和发布治理
- `skill` 应作为可复用能力层与 Agent 主线融合，而不是替代顶层 Agent Spec

这条路线已经在 `.claw/decisions.md` 中固化为长期架构决策。

## 3. 主要模块地图

### 3.1 仓库结构

- `backend/`：Java 21 + Spring Boot 3 后端
- `frontend/`：React + Vite 前端
- `docs/`：产品、架构、部署与安全文档
- `.claw/`：项目状态文件，作为 AI 协作的持久记忆层
- `scripts/`：本地联调、质量检查、演示脚本

### 3.2 前端

前端当前是双入口结构：

- `/`：助手工作台
- `/admin/*`：管理后台

其中助手工作台已经包含两块主要体验：

- 会话聊天工作台
- Agent Builder 工作台

Agent Builder 当前已经具备：

- Agent 定义基础表单
- 自然语言流程 Spec 编辑
- 知识挂载与工具白名单
- 编译结果区
- 只读流程图预览
- 最小调试运行视图

### 3.3 后端

后端当前采用 **模块化单体** 作为 MVP 形态，优先保持清晰边界，而不是过早拆微服务。

当前主干能力包括：

- 鉴权与登录
- 多组织上下文
- 聊天与流式输出
- 知识库与文档处理
- 模型与工具管理
- 运维与审计接口
- Agent 编译接口

## 4. 当前产品形态

### 4.1 助手端

助手端主要服务员工使用场景：

- 发起对话
- 勾选知识库参与 RAG
- 调用 AI 模型获取回答
- 进入 Agent Builder 编写或调试 Agent

### 4.2 管理端

管理端主要服务组织管理员：

- 维护知识库和文档
- 配置模型与工具
- 查看运维与审计信息
- 管理组织内用户角色

## 5. 已经明确的关键架构决策

截至目前，项目已经明确了几条后续开发不能轻易偏离的原则：

1. 前后端分目录维护，保持双应用工作区结构。
2. 后端先采用 Spring Boot 模块化单体，后续再按需要拆分。
3. 助手端与管理端分离，避免员工使用和系统管理混在同一控制台。
4. Agent Builder 放在助手侧工作台内演进，而不是独立后台页。
5. Agent 工作流坚持文本优先，自然语言 Spec 是主输入。
6. 图形流程图只是编译产物的只读预览，不作为 source of truth。

## 6. 当前开发进展

围绕 Agent Builder，当前已经完成：

- 文本优先的 Spec 编辑器
- 知识库与工具授权区
- compile 接口接入
- workflow code / manifest / preview graph 产物返回
- Mermaid 只读流程图预览
- 调试面板中的路径高亮观察视图
- 更紧凑的单主列构建页布局
- 编译结果 tab 化

这说明项目已经从“纯前端骨架”进入了“前后端编译闭环已打通，开始补运行与保存能力”的阶段。

## 7. 当前优先级

按 `.claw/current-status.md`，当前最值得继续推进的是：

1. 补 `AgentSpec` 保存接口，让 Builder 从临时前端态进入可持久化草稿态。
2. 将试运行从前端模拟切到真实 debug 接口，形成真实执行观察链路。
3. 继续补充 Agent 版本、发布和治理能力，逐步闭合从编写到上线的链路。

## 8. 文档与状态文件如何配合

这个项目同时维护两类信息：

- **长期说明文档**：放在 `docs/` 和 `README.md`
- **当前状态与协作记忆**：放在 `.claw/`

推荐读取顺序：

1. 先看 `.claw/current-status.md`，了解当前阶段与下一步。
2. 再看本文件，建立项目全貌。
3. 当需要理解 Agent Builder 与 skill 的统一方向时，优先看 `docs/agent-skill-fusion-design.md`。
4. 当需要理解 Agent Builder 原始路线时，继续看 `docs/natural-language-agent-workflow-framework.md`。
5. 当需要理解助手端新的“智能体 -> 会话 -> 消息”层次时，继续看 `docs/agent-conversation-hierarchy-design.md`。
6. 当需要理解部署或安全边界时，再分别查看 `docs/deploy-runbook.md` 与 `docs/security-and-compliance-checklist.md`。

## 9. 一句话总结

这个项目正在从“企业多组织 AI 助手基础能力”逐步演进到 AgentCiCi 的“企业智能体运行与治理平台”产品形态，而当前最关键的落点就是把 **Agent Builder** 从可视化原型推进到真实可保存、可调试、可发布的执行闭环。
