# AgentCiCi 智能体记忆功能使用说明

## 1. 这项功能是做什么的？

记忆功能让智能体在合规、授权的范围内，记住与某位用户或某个会话有关的必要信息。这样用户下次再来咨询时，智能体可以少问重复问题，更快理解上下文。

例如，用户上次已经说明“希望通过邮件接收通知”，下次咨询时，智能体可以在允许的范围内参考这项偏好，而不是再次询问。

记忆功能适用于客服、CRM、门户、业务工作台等接入 AgentCiCi 的外部应用。它是一项通用平台能力，不绑定某一个具体业务系统。

## 2. 记忆不等于聊天记录

请把它理解为“整理后的要点”，而不是“把所有对话永久保存下来”。

| 内容 | 是否作为长期记忆 | 说明 |
|---|---|---|
| 当前对话最近几轮内容 | 临时使用 | 用于理解本次问题，不会无限累积到模型上下文。 |
| 会话摘要、待办、未完成承诺 | 可保存 | 帮助下一次接续处理。 |
| 用户明确确认的偏好或事实 | 可作为候选 | 例如通知偏好、已确认的联系偏好。 |
| 价格、权益、合同、赔付等重要结论 | 默认需要人工审核或实时系统确认 | 不能只依赖历史记忆下结论。 |
| “你好”“你好呀”“你好吗”等重复问候 | 不保存 | 系统会限频，也不会调用模型、工具或写入记忆。 |

## 3. 它能带来什么体验？

### 少问重复问题

在用户身份和权限允许的前提下，智能体可以参考已确认的偏好、当前会话摘要和未完成事项。

### 跨会话接续处理

用户隔一段时间再来问“上次的事情处理得怎么样了”，智能体可以先参考已有摘要和待办，再调用业务系统获取最新状态。

### 不同智能体之间的必要交接

当对话从一个业务智能体转交给另一个智能体时，系统只传递完成当前任务所需的最小信息，避免用户重复说明已经确认的内容。

### 可治理、可撤销

经过授权的管理员可以审核候选记忆、撤销错误记忆，或按规则删除某个主体的记忆。

## 4. 谁能看到哪些记忆？

记忆不是所有智能体都能看见。AgentCiCi 会同时检查以下边界：

- 组织：不同组织的数据互相隔离；
- 外部应用：同一个外部用户标识在不同应用中不会自动共享；
- 主体：只能读取当前用户、当前会话或当前业务对象允许的记忆；
- 智能体范围：智能体私有记忆不会默认提供给其他智能体；
- 时效：过期、撤销或删除的记忆不会再被使用；
- 敏感级别：默认不会把内部或敏感内容注入面向外部用户的提示词。

向量检索只用于寻找可能相关的脱敏片段。最终是否可用，仍要回到平台的权威记录中再次核验权限、状态和有效期。

## 5. 管理员如何启用记忆？

启用前，请先明确要为哪个 Agent、哪个外部应用和哪类主体提供记忆服务。

基本流程如下：

1. 创建或选择目标 Agent，并确认谁拥有其管理权限。
2. 为外部应用创建 API 凭据。
3. 为该凭据配置记忆绑定：应用编码、主体类型、身份等级，以及允许的命名空间。
4. 由外部应用服务端调用 AgentCiCi OpenAPI；客户端页面不能自行指定组织、应用、Agent 或记忆范围。
5. 使用非敏感测试主体验证：有绑定时可获得授权上下文；禁用绑定后应安全降级为“不使用记忆”。

> 重要：外部应用只能传递自身的用户标识和会话标识。应用、主体类型、身份等级、允许读取的范围等安全属性，必须以平台中保存的凭据绑定为准。

## 6. 候选记忆如何审核？

智能体或规则只能提出“候选记忆”，不能直接把内容变成长期可用记忆。

管理员审核时可按下面的方法判断：

1. 确认内容是否真实、明确，且确实与当前主体有关；
2. 判断是否需要业务系统的实时数据作为依据；
3. 判断是否包含敏感信息、权益承诺或高风险结论；
4. 选择批准或拒绝，并填写简短原因。

只有批准后的候选，才会形成可被授权智能体读取的有效记忆。重复审核、跨组织或跨 Agent 的操作会被拒绝。

## 7. 如何处理错误、过期或不应保留的记忆？

### 撤销一条记忆

适合“这条信息不再正确，但不需要删除整个主体”的情况。例如，用户已经改变通知偏好。

撤销后：

- 该记忆立即不再参与后续回答；
- 对应的派生向量会被移除；
- 系统保留不含正文的最小审计记录，用于追溯操作。

### 删除某个主体的记忆

适合用户提出删除请求，或外部应用确认该主体不应继续保留相关记忆的情况。

删除时，系统会处理该主体关联的记忆、候选、证据引用和会话摘要，并同步清理派生向量。若组织处于法律保留（legal hold）状态，删除会被安全拒绝。

### 等待自动过期

带有效期的记忆在到期后会自动失效，不再进入智能体上下文。法律保留期间不会执行这类清理。

## 8. 智能体会不会“记错”？

有可能，因此记忆功能有以下保护：

- 重要事实优先以实时业务系统和人工确认结果为准；
- 高风险事项默认不依赖模型自动长期写入；
- 记忆有来源、置信度、有效期和状态；
- 过期、撤销、删除和冲突的记忆不会继续被使用；
- 管理员可以审核、拒绝和撤销；
- Trace 会记录“是否注入记忆、是否被截断、命中了多少条”，但不会记录记忆正文或外部用户标识。

因此，记忆用于帮助对话衔接，不用于取代订单、合同、工单、账户权限等实时业务事实。

## 9. 常见问题

### 用户一直重复说“你好”，为什么智能体不一直聊天？

系统会识别连续、语义相近的问候。前几次会礼貌引导用户说明需求，之后会进入限频模式，避免反复调用模型、知识库和业务工具。用户一旦提出新问题或要求人工客服，就会恢复正常处理。

### 用户的所有历史聊天都会被保存吗？

不会。平台重点保存经过筛选和治理的摘要、待办、已确认事实或其他必要记忆。原始聊天记录是否保留、保留多久，由外部应用及其合规策略决定。

### 外部应用 A 与外部应用 B 使用相同用户 ID，会共享记忆吗？

不会自动共享。应用编码是隔离条件之一。只有在平台显式配置并且权限允许的情况下，才会在受控范围内共享必要信息。

### 管理员能看到完整的用户隐私和向量内容吗？

不应将向量内容作为业务查看对象。平台的管理与审计记录遵循最小必要原则；面向外部用户的运行时默认不会注入内部或敏感记忆。

### 删除后还能被检索到吗？

删除或撤销后，关系库记录会立即变为不可读取；即使向量物理删除发生延迟，也不能绕过关系库授权重新被使用。

## 10. 使用建议

- 先从低风险内容开始，例如偏好、会话摘要和待办；
- 价格、权益、合同、赔付、账户权限等信息始终以实时业务系统为准；
- 为不同外部应用分别配置凭据和绑定，不共用不清晰的身份范围；
- 定期审核候选记忆和已撤销项，避免旧信息长期存在；
- 发生争议、投诉或法律保留时，先确认组织保留策略，再执行删除或清理；
- 上线前使用非敏感测试主体完成“启用、禁用、审核、撤销、删除、Trace”全流程验收。

## 11. 获取帮助

如果需要配置外部应用接入、调整记忆范围、排查未召回或误召回问题，请联系组织管理员或 AgentCiCi 平台管理员，并提供：

- 外部应用名称或应用编码；
- Agent 名称或 ID；
- 测试主体和会话标识（请勿在工单中直接提供敏感正文）；
- 大致发生时间；
- Trace ID（如有）。

平台管理员可以据此检查绑定是否启用、记忆状态和有效期、权限范围，以及 Trace 中的状态型证据。
