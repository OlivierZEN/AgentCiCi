# FEAT-047 顶层规范文档减重与职责拆分

## 背景

当前仓库根目录的 `AGENTS.md`、`PRODUCT.md`、`DESIGN.md` 都在描述项目规则，但边界已经开始重叠：

- `AGENTS.md` 同时承载技能要求、PR 流程和部分设计语气。
- `PRODUCT.md` 既写产品定位，也重复了不少界面风格要求。
- `DESIGN.md` 既写风格基线，也重复了产品语气与禁用项。

这种重复会直接抬高 AI agent 的上下文成本，也会增加后续维护时“一处改了、另一处没改”的漂移风险。

## 目标

- 降低这三份顶层规范的总阅读成本。
- 明确每份文档只负责一类事实源。
- 保留项目必须执行的硬规则，不因为精简而丢约束。

## 范围

- 重写 `AGENTS.md`，只保留项目执行规则、PR 默认流程和设计事实源分工。
- 重写 `PRODUCT.md`，只保留产品定位、首要场景、差异化与非目标。
- 重写 `DESIGN.md`，只保留 `鎏金账房` 的人类可读摘要、页面质量流程和关键 UI 规则入口。

## 不在本次范围

- 不改 `DESIGN.json` 的 token、组件规则和结构化设计数据。
- 不批量回写所有历史 spec、README 或代码注释中的旧表述。
- 不引入新的产品方向、视觉语言或页面实现要求。

## 文档职责拆分

- `AGENTS.md`：项目级执行规则，告诉 agent 先做什么、PR 默认怎么处理、设计事实源在哪里。
- `PRODUCT.md`：产品是什么、先卖什么、靠什么区分、明确不做什么。
- `DESIGN.md`：认证后产品面的共享设计基线，人类快速阅读版。
- `DESIGN.json`：详细 token、组件规则、页面实现流程的结构化事实源。

## 验收标准

- 三份文档都改成中文描述。
- 三份文档总长度明显下降，且不再互相大段重复。
- `AGENTS.md` 仍保留 `cc-aidev-guidelines-common` 托管声明块。
- `DESIGN.md` 明确把详细规则指向 `DESIGN.json`，而不是继续复制 token 细节。

## 交接说明

- 后续如果要加新的跨页面设计规则，优先更新 `DESIGN.json`，再视需要在 `DESIGN.md` 增加一行摘要。
- 后续如果要改产品定位，优先更新 `PRODUCT.md`，不要把定位结论散落到 `AGENTS.md`。
