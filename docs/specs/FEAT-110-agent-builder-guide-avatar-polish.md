# FEAT-110 - 智能体构建说明与头像交互精修

## 背景与目标

- 当前“智能体构建说明”位于已有页面框架内，却再次使用带背景、边框、圆角和内边距的说明卡片，形成多余的盒中盒结构，并放大了说明文字与页面外层框的距离。
- 当前头像区把“上传图片”和“清除头像”两个实体按钮长期并列展示，高频更换动作与低频移除动作层级相同，占用横向空间，也不符合常见头像编辑入口的操作预期。
- 本次目标是在不改变 Agent 定义、裁剪、草稿保存与发布流程的前提下，收紧说明区节奏，并把头像操作收敛为以头像本身为入口的轻量菜单。

## 范围

### In Scope

- 移除“智能体构建说明”外层的背景、边框和圆角。
- 去掉说明区额外的大块内边距，使说明文字更靠近页面外层框，同时保留页面级安全 gutter。
- 将头像预览改为可点击、可键盘聚焦的编辑入口。
- 头像 hover 或 focus 时显示克制的相机提示；点击后打开紧凑操作菜单。
- 菜单提供“上传头像”或“更换头像”；仅已有自定义头像时显示“移除头像”。
- 移除头像后立即回退为 Agent 名称首字，不额外弹确认框；更改仍沿用现有草稿保存机制。
- 补充聚焦测试，并完成真实桌面端截图与 hover、focus、菜单开关、裁剪入口和移除回退检查。

### Out Of Scope

- 不改变头像文件类型、裁剪规则、存储字段、保存 API 或发布逻辑。
- 不新增头像素材库、系统预设头像、拖拽上传、拍照入口或图片编辑能力。
- 不改变页面整体双栏结构、策略开关行为、主题 token 或跨页面组件语汇。
- 不新增移动端布局、移动端截图或移动端自动化测试。

## 用户场景

- 平台运营人员进入 Agent 定义页时，可以先快速扫读构建流程，不会被一张额外说明卡片抢占层级或产生过大的页面留白。
- 用户需要设置或更换头像时，直接点击当前头像，并从就近菜单选择上传；原有裁剪流程继续生效。
- 用户已经设置自定义头像时，可以在同一菜单中选择“移除头像”，界面立即显示名称首字作为回退，随后通过“保存草稿”持久化。
- 用户使用键盘时，可以聚焦头像入口、打开菜单并看见清晰但克制的焦点反馈。

## 现状与约束

- 当前实现位于 `frontend/src/assistant/AgentBuilderShell.tsx` 与 `frontend/src/assistant/cici-ui.css`，聚焦测试位于 `frontend/src/assistant/AgentBuilderShell.test.ts`。
- 现有 `beginAvatarCrop`、裁剪弹窗和 `draft.avatarBase64` 数据流已经可用，本次只重组入口，不复制上传或裁剪逻辑。
- 页面属于认证后 `product` register，必须保持“鎏金账房”的暖象牙底、墨色文字、紧凑密度和香槟金结构线。
- `DESIGN.md` 与 `DESIGN.json` 已明确禁止在已框定产品面板内增加背景盒，并要求内联操作使用轻量文本或图标语汇。

## 方案比较与决策

### 方案 A：头像点击菜单，采用

- 头像本身是唯一常驻入口；点击后菜单承载上传/更换与条件显示的移除动作。
- 优点是符合常见头像编辑心智，视觉最干净，低频危险动作不会长期占位。
- 代价是上传动作增加一次点击，但在低频配置场景中可接受。

### 方案 B：头像点击直接上传，旁边保留移除文字

- 更换头像少一次点击，但头像入口含义不够显式，移除动作仍持续占用横向空间。

### 方案 C：头像悬浮相机按钮，旁边保留垃圾桶图标

- 两个动作都直观，但仍保留两个长期控件，对紧凑治理表单偏重。

用户已确认按方案 A 实现。

## 交互与组件设计

### 构建说明

- 保留标题和三段现有说明文案，不改变流程语义。
- 容器改为透明、无边框、无圆角；只使用较小的底部节奏与最少量水平内距。
- 不修改 `.cici-builder` 的全局页面 gutter，避免 Agent 定义与后续生命周期区域整体贴边。

### 头像入口与菜单

- 使用语义化 `button` 包裹头像视觉，提供明确 `aria-label`、`aria-haspopup="menu"` 与展开状态。
- hover 和 focus-visible 时在头像上显示相机图标或简短“编辑”提示，不缩放、不位移、不增加阴影。
- 菜单锚定在头像附近，使用不透明暖象牙表面、浅金边和紧凑行高；菜单项不使用逐行卡片背景。
- 无自定义头像时首项文案为“上传头像”，有自定义头像时为“更换头像”。
- “移除头像”仅在 `draft.avatarBase64` 非空时出现，使用危险文字色但不增加危险按钮块。
- 上传项触发现有隐藏文件输入；选择文件后关闭菜单并进入现有裁剪流程。
- 移除项清空 `draft.avatarBase64`、关闭菜单并显示名称首字，不弹二次确认。
- 点击外部或按 Escape 关闭菜单；关闭后焦点行为保持可预测。

## 数据流与异常处理

- 上传链路保持“文件选择 → `beginAvatarCrop` → 裁剪弹窗 → 更新 `draft.avatarBase64`”。
- 取消文件选择或取消裁剪不改变当前头像。
- 文件读取、格式或裁剪错误继续复用现有提示，不新增第二套错误状态。
- 移除头像只修改当前草稿；未保存离开时沿用现有草稿变化处理，不单独持久化。

## 接口与数据影响

- 无 API、数据库、事件、迁移或保存 payload 变化。
- 不改变 `draft.avatarBase64` 的类型与兼容行为。
- 仅调整前端渲染结构、局部状态、样式和测试。

## 验收标准

- “智能体构建说明”不再显示背景、边框或圆角，文字与页面外层框的视觉距离明显缩小。

- 页面不再长期显示“上传图片”和“清除头像”两个实体按钮。
- 点击或键盘激活头像会打开菜单；上传/更换继续进入现有裁剪流程。
- 只有存在自定义头像时才显示“移除头像”；移除后立即显示名称首字，并产生可保存的草稿变化。
- hover、focus-visible、打开、关闭、Escape、外部点击和禁用/无头像条件均具有稳定状态，不出现缩放、阴影或布局抖动。
- 聚焦 Vitest、前端全量测试、生产构建与 `git diff --check` 通过。

## 风险与回滚

- 风险：头像菜单的外部点击监听与裁剪弹窗发生竞争。实现时应先关闭菜单，再触发现有文件选择与裁剪链路，并用聚焦测试覆盖。
- 风险：把头像视觉包进原生按钮后继承全局按钮阴影、位移或背景。局部样式必须重置所有状态，并在浏览器中检查 computed style。
- 风险：说明区去框后层级过弱。保留标题字重与金色标题文本，通过文字层级而非背景盒建立分组。
- 回滚：恢复原头像并列操作与说明区样式即可；无数据与接口回滚。
