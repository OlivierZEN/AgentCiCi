# FEAT-179 - 统一模型调用治理

## 背景与目标

当前聊天、知识库、视觉 OCR、语音识别、联网、代码解释器和部分 Skill 调用分别读取环境变量、集成应用密钥或模型厂商配置。部分代码带有具体模型默认值，缺少凭据时还会回退到默认百炼客户端。该行为会造成模型、厂商和密钥错配，且无法从平台场景模型路由审计实际调用。

本功能把所有模型调用收敛到平台受管的 `provider + model + credential` 解析结果。每一个调用场景必须有已生效的平台场景路由；厂商、模型或凭据不满足条件时明确失败，不做环境变量或其他厂商回退。

## 范围

### In Scope

- 建立唯一的服务端模型调用解析器，返回受校验的 provider、model、API 地址和凭据；调用方不得再自行拼接或读取模型密钥。
- 场景路由覆盖聊天、Skill 创作、本体建模、会议纪要、客户洞察、知识库 embedding、视觉 OCR、实时/文件 ASR、代码解释器、联网搜索和网页抓取。
- 模型厂商目录只提供已启用且显式选定的模型；embedding 与其他能力通过能力/场景路由分别校验。
- 知识库索引及检索使用 `knowledge-embedding` 场景路由；保存知识库设置与启动索引前均校验路由，避免异步 401。
- 代码解释器、联网搜索和网页抓取不再保存独立模型、API 地址或 API Key；仅保留非模型运行限制。
- 移除生产调用路径中的具体模型默认值和默认百炼客户端回退；保留测试 fixture 中的显式值。
- 为统一解析、失败关闭、知识库 embedding 和受管工具补充定向测试。

### Out Of Scope

- 不自动迁移、修改或补发任何 UAT/生产厂商凭据。
- 不替用户选择供应商、模型或购买模型能力。
- 不实现未受支持模型协议的通用适配器；协议不兼容时必须拒绝配置或执行。

## 用户场景

- 平台运营为每个业务场景选择已启用、已选定且具备目标能力的模型。组织管理员只能使用这些受管结果，不能提供或覆盖模型密钥。
- 组织管理员上传知识库文档时，索引使用平台 `knowledge-embedding` 路由。路由未配置时在开始索引前返回明确错误，不调用百炼或其他默认客户端。
- Agent 调用代码解释器、联网搜索或网页抓取时，工具从对应场景路由获取模型和凭据；未配置则返回可审计的失败结果。
- 语音/视觉能力必须使用其对应场景路由；当前协议只支持的厂商与模型不匹配时拒绝执行。

## 现状与约束

- `ModelProviderService` 已是厂商凭据与模型目录的权威服务，但 `resolveRuntimeModelRoute` 仍存在默认候选和 Agent 偏好回退。
- `AliyunBailianClient` 的实现是 OpenAI-compatible HTTP 客户端，名称不能成为绕过厂商解析的理由。
- `AliyunAsrService` 当前直接读取百炼环境变量；文件 ASR 协议只支持百炼，因此路由校验必须明确其协议限制。
- 知识库当前可以保存任意 embedding provider/model；默认 local-hash 和 local profile 的百炼 embedding 都可能绕过平台场景路由。
- 现有集成应用可能包含历史的 `apiKey`、`apiBaseUrl` 和 `model` 字段；新版本不得读取它们，UI 不再显示或编辑它们。

## 方案设计

1. 在模型服务建立受治理的场景解析接口。它必须验证：路由存在、厂商已启用、模型属于该厂商的已选模型、调用协议支持该场景、地址存在且需要时密钥非空。
2. 调用方仅接收不可变的解析结果；任何解析失败抛出带稳定错误码的业务异常。通用聊天客户端只接受解析结果，不再使用环境默认地址、密钥或模型。
3. 平台模型路由增加非聊天场景。模型目录按能力过滤；OneKeyToken 可以用于其已配置且支持的聊天场景，但不会被默认为 embedding、ASR、视觉、联网或代码解释器。
4. 知识库将 embedding 模型视作路由结果。旧的知识库元数据只用于标记已有向量；重新索引时始终使用当前路由。改变 embedding 路由后须重建相应索引。
5. 受管工具配置只保留 timeout、输入限制等非敏感运行参数。工具执行前解析其场景模型，并使用平台厂商凭据。

## 接口与数据影响

- 平台模型路由 API 增加上述场景；现有场景保持路径与请求格式兼容。
- 知识库 embedding 选项和保存接口改为只读显示当前路由或拒绝任意厂商/模型覆盖；历史字段保留以支持向量审计。
- 集成应用 API 对代码解释器、联网搜索、网页抓取忽略并拒绝新的独立模型凭据字段；历史密文不再参与执行。
- 不新增跨项目数据库访问或跨仓依赖。

## 验收标准

- 所有生产模型调用路径都通过统一解析器，静态扫描不再发现生产默认模型名、环境模型密钥或无凭据聊天调用。
- 每个模型调用场景没有有效路由、模型不在已选目录、厂商停用或凭据缺失时均失败关闭；不会向默认百炼地址发起请求。
- 知识库在 embedding 路由缺失时不写入向量，配置合法时使用路由返回的 provider/model/credential。
- 联网、代码解释器与网页抓取不再读取集成应用中的 API Key、地址或模型。
- 定向单元/集成测试、后端编译和前端构建通过；本轮不发布 UAT/生产。

## 风险与回滚

- 强制路由会使历史未配置环境的模型能力暂时不可用，这是预期的安全失败；运营需先配置场景路由再启用能力。
- embedding 路由变更可能与既有向量维度不兼容；必须提示重建索引，不能混用向量。
- 代码解释器和联网能力具有供应商协议要求；路由指向不兼容模型时必须返回明确失败，不降级到其他模型。
- 回滚仅回滚 AgentCiCi 应用版本和配置契约，不删除向量或厂商配置。

## 实现进展

- 2026-08-13：新增 `ModelInvocationResolver`。场景路由不再使用首个候选、Agent 偏好或环境变量回退；厂商初始化不再从应用环境变量注入百炼凭据。
- 2026-08-13：聊天、会议纪要、技能创作、本体建模、客户洞察、知识库/记忆 embedding、图片 OCR、实时/文件 ASR、代码解释器及联网搜索/网页抓取均已迁移到场景解析。代码解释器与联网工具配置仅保留 timeout、输入限制；迁移 V112/V113 清理知识库 local 占位和历史工具独立凭据。
- 2026-08-13：知识库管理页改为只读显示 `knowledge-embedding` 路由结果，不再提供按知识库覆盖厂商或模型的控件。后端干净编译、定向 10 项测试、前端生产构建与 diff check 均通过；UAT/生产未修改。
