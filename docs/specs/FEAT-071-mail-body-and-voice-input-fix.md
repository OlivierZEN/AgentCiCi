# FEAT-071 - 对话邮件正文展示与语音输入识别修复

## 背景

线上 `2.1.4` 对话中，用户要求“看下这封邮件内容”时，助手只展示了 `email_search` 搜索结果和 `messageId`，没有继续读取并展示邮件正文。截图中同时出现语音输入提示“未识别到有效语音内容”，说明实时 ASR 前端对结果事件和停录收尾不够稳健。

## 目标

- 当用户要求查看、阅读或展开某封邮件内容时，如果 `email_search` 已经唯一命中一封邮件，编排层必须继续获取该邮件正文，最终回答中可直接展示主题、发件人、收件人、时间和正文摘要或正文前段。
- 保留 `email_get_message` 的显式读取能力，避免用户需要复制 `messageId` 后二次追问。
- 语音输入必须兼容后端 ASR 返回的常见文本字段形态，并在用户停止说话或点击停止后给最终识别片段足够的回传窗口。
- 未识别到文本时仍应给出明确提示，但不能因为前端字段解析过窄或过早关闭 WebSocket 而误报。

## 范围

- 后端对话编排：
  - 邮件搜索命中唯一 `messageId` 且当前问题包含“看下/查看/读/正文/内容/详情”等正文意图时，不能把单次 `email_search` 结果当成最终完成。
  - 工具规划停止判断要识别上述邮件正文意图，允许模型继续调用 `email_get_message`。
  - 增加可测试的正文意图与单一 `messageId` 提取逻辑。
- 前端语音输入：
  - `useAsrVoiceInput` 兼容 `text`、`transcript`、`result`、`payload.text`、`payload.output.sentence.text`、`sentence.text` 等 ASR 文本字段。
  - 停止录音后延长 WebSocket 关闭延迟，避免 final 事件被 300ms 收尾窗口截断。
  - `finished` 事件到达时可主动结束会话。
- 验证：
  - 增加后端单元测试覆盖邮件正文意图下不跳过工具规划、单一邮件 id 提取。
  - 增加前端单元测试覆盖 ASR 文本提取。
  - 运行 focused 后端测试、前端测试或构建、静态检查。

## 非目标

- 不改 POP3/SMTP 账号配置、邮件发送确认策略和真实邮件正文抓取协议。
- 不引入新的语音供应商。
- 不调整认证后产品页视觉语言。
- 不改变生产发布脚本和版本策略。

## 验收标准

- 对话中用户说“和利时环境大数据表排查分析 看下这封邮件内容”时，如果最近邮件搜索唯一命中，助手会继续获取正文，而不是只输出搜索命中列表和 `messageId`。
- 语音识别事件只要携带可识别文本字段，前端都能汇入输入框和最终发送文本。
- 停录后最终 ASR 文本不会因短延迟关闭 WebSocket 被丢弃。
- 所有改动有任务授权、测试报告和可追溯提交。
