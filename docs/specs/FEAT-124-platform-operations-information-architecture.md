# FEAT-124 - 运营管理端信息架构与独立主题重构

## 来源与已确认设计

- 用户指出现有 `/platform/*` 把策略编辑、版本历史、目录、详情和说明堆叠在同一页面，一级平铺菜单不足以支撑当前能力。
- 用户选择本会话 Product Design 的第 2 张「运营中枢」桌面稿，确认其以“待办优先队列 + 治理健康摘要 + 最近变更 + 风险跟进 + 右侧渐进式详情”为主结构。
- 用户明确二级菜单不是给旧菜单加分组，而是按功能拆出不同页面；不得改变、遗漏或混淆任何现有平台功能。
- 用户要求平台端拥有与用户/Admin 相同的八套受控主题，但平台账号的设置与本地回退均独立。

## 目标与非目标

### 目标

1. 平台运营人员先在总览判断待办，再通过二级任务页进入完整工作区。
2. 保留所有现有 `/platform/*` API、数据、权限、高风险确认和旧入口的兼容路径。
3. 列表页只承担搜索、筛选和扫描，低风险查看使用抽屉，配置/草稿/版本/发布/回滚使用独立路由。
4. 平台端复用受控八主题，但以独立账号同步和独立本地缓存键保存偏好。

### 非目标

- 不修改后端业务 API、数据库、权限模型、技能/模型/租户/计费事实或发布语义。
- 不新增移动端布局、移动端截图或移动端自动化测试。
- 不改变 `/platform/login` 已批准的像素锁定例外，也不改变 `/admin/*` 或用户端主题偏好。

## 目标信息架构

```text
总览
└── 运营总览                         /platform

能力治理
├── 技能目录                         /platform/skills
├── 技能设置                         /platform/skills/:skillId
├── 策略与版本                       /platform/skills/policies
├── 依赖与影响                       /platform/skills/dependencies
├── 模型厂商与目录                   /platform/models/providers
├── 场景模型路由                     /platform/models/routes
├── 平台集成                         /platform/integrations
├── 工具目录                         /platform/tools
└── 工具治理                         /platform/tools/:toolName

运营管理
├── 套餐目录                         /platform/billing
├── 套餐版本编辑                     /platform/billing/editions/:editionCode
├── 加购包与 Credits                  /platform/billing/packages
├── 加购包设置                       /platform/billing/packages/:packageCode
├── 租户目录                         /platform/tenants
```

旧的 `/platform/models`、`/platform/skills`、`/platform/tools`、`/platform/billing`、`/platform/evaluation` 保持为各自目录或总览页。原先混在页面内的 tab/选中状态改为可书签化子路由；租户详情、线索和审计入口保持现有路径。

## 页面与交互

### 运营总览

- 首位显示最多三条待办优先队列，每条都有影响范围、发生时间和唯一“处理”入口。
- 后续依次是紧凑治理健康、最近变更和风险跟进，均跳转到对应独立工作区。
- 低风险事项可在右侧抽屉中查看，不丢失上下文；抽屉中的“开始处理”必须进入完整页面，不在抽屉中编辑高风险配置。

### 目录、详情与编辑的边界

- 技能、工具、套餐、租户和评测资产目录页仅包含可筛选列表、少量扫描字段和三点行操作。
- 拆页以任务复杂度为准，不能把“列表与编辑分离”当成机械规则。核心策略、技能模板、工具治理、套餐版本、包配置等复杂或高风险过程使用独立编辑页；模型厂商凭据、检测与该厂商已选模型属于连续轻量任务，可同页完成。场景模型路由因跨厂商决策语义独立，保留独立页面。
- 版本、依赖与影响范围不再常驻编辑器下方，而是“策略与版本”“依赖与影响”或对象详情内轻量 tab/子路由。
- 发布、回滚、销毁继续使用明确的 modal 确认和原有权限边界。

### 租户应用中心

- `/platform/tenants/:orgId` 是平台运营人员的租户应用页，不属于 `/admin/*` 组织管理端。页面只保留当前租户身份与“应用中心”卡片，不展示共享的保留、导出、预演、销毁记录或顶层生命周期操作。
- 应用卡片的归属是当前顶层租户。卡片之间独立展示开通、运行或失败状态，任何单个应用的状态不得改写顶层租户状态。
- 每个应用都有自己的生命周期、保留、导出、预演与销毁能力；这些能力必须进入所属应用的独立管理页面或服务契约，绝不作为租户级共享区块出现，也不得在应用间复用字段或状态。
- AgentCiCi 是当前租户的基础应用。卡片只展示当前已验证的组织标识、成员数、应用状态与开通方式；没有应用维度的许可、到期或用量事实时必须显示“未配置/未记录”，不得用演示数值替代。
- AgentCiCi 卡片整体可点击，并进入 `/platform/tenants/{orgId}/applications/agentcici`。该路由承载原有租户保留、导出、预演和销毁治理，页面标题、返回入口和语义均明确为 AgentCiCi 应用生命周期；卡片页不重复展示这些内容。
- Semattice 卡片的正式名称是“Semattice 业务数据与语义运行底座”，副标题为“面向智能体的业务数据与语义运行底座”。它不是知识库或文档索引产品；不得展示知识库、文档、问答、同步任务等不属于其实际能力的数据。
- 未开通的 Semattice 卡片展示当前租户 `org_id` 作为待绑定的 `company_id`、开户来源、AgentCiCi 受控身份校验和 HTTP API/MCP/CLI 接入面。平台运营人员可执行“开通 Semattice”；该动作调用 FEAT-134 定义的 `POST /platform/tenants/{orgId}/semattice-provisionings`，并传递一次性幂等键、租户显示名、服务等级和 entitlements。开户成功后仅更新 Semattice 卡片状态，不影响 AgentCiCi 卡片或顶层租户状态。
- 应用中心使用当前平台主题 token，保持紧凑、可扫描的运营信息密度。卡片是独立可操作应用实体，内部用事实行和细分隔线组织信息，不嵌套次级卡片，不引入营销式 hero 或装饰性渐变。

### 导航与主题

- 一级菜单只表达领域，二级菜单只表达可独立完成的任务。一级为可访问的 button，叶节点为 NavLink；当前领域、叶节点、展开和键盘焦点均有清晰语义。
- 平台偏好页展示既有八主题：鎏金账房、CRM 标准蓝、蓝色海洋、樱花粉语、熏衣紫语、牛油果小调、红酒醇香、星河幻境。
- 平台偏好通过既有平台账号端点同步，使用平台专属 localStorage 键；绝不读取、覆盖或写入用户/Admin 端的主题缓存。主题只映射 token，不改变菜单几何、控件尺寸、密度、图标、动画或滚动模式。

## 功能保全对照

| 现有能力 | 新工作区 | 保全要求 |
| --- | --- | --- |
| 标准技能、模板草稿、发布/回滚、核心策略、版本历史、依赖图 | 技能目录、技能设置、策略与版本、依赖与影响 | 保留所有请求、版本判断和影响数据，只拆页面职责。 |
| 模型厂商、凭据检测、模型目录、场景路由 | 模型厂商与目录、场景模型路由 | 同页完成单厂商的凭据、检测与模型目录；保留保存、检测、拉取、启停与清除路由操作。 |
| 平台集成、工具配置与依赖 | 平台集成、工具目录、工具治理 | 保留既有配置/保存流程。 |
| SaaS/私有化版本、容量/模块/服务包、Credits | 套餐目录、套餐版本编辑、加购包与 Credits、加购包设置 | 保留部署筛选、版本保存、包保存和审计原因。 |
| 租户开通、应用开通、保留、导出、预演、销毁 | 租户目录、租户生命周期与应用中心 | 保留独立高风险确认与所有历史记录；Semattice 开通仅通过 AgentCiCi 受控开户契约执行。 |
| 评测资产、用例、发布/归档、运行洞察 | 质量总览、标准评测资产、运行洞察 | 保留不可变版本、隐藏用例与发布门禁。 |
| 网站预约线索、平台审计 | 注册与演示线索、平台审计 | 路径、筛选、状态更新和脱敏展示不变。 |

## 技术范围与依赖

- 前端仅重构 `frontend/src/platform/**`、平台路由、平台作用域样式与主题偏好组件；必要时新增定向前端测试。
- 不复制业务逻辑，优先从现有复合页面抽取目录、详情、编辑视图以避免 API 行为漂移。
- 跨页面规则同步维护 `DESIGN.json`、`DESIGN.md`。
- TASK-218 当前独占 `PlatformModelsPage.tsx` 的厂商目录能力修复；本任务在其合并前不得编辑该文件，模型子路由拆分在该依赖解除后进行。

## 本轮落地状态（2026-07-22）

- 已落地：二级领域导航、运营总览的待办队列与低风险详情抽屉、技能目录/设置/策略/依赖路由、工具目录/治理路由、套餐目录/版本/加购包/包设置路由、评测总览/资产/运行洞察路由，以及平台独立主题偏好页。
- 主题隔离：平台读取和写入 `cici-platform-theme`；用户/Admin 仍使用既有 `cici-product-theme`。平台服务端继续通过 `/auth/platform/me/theme` 保存八主题偏好。
- 已收敛模型信息架构：TASK-218 合并后的厂商能力边界保持不变；“模型厂商与目录”将单厂商凭据、检测与已选模型保留在同页，`/platform/models/catalog` 仅作为兼容跳转；“场景模型路由”继续作为独立任务入口。
- 已落地租户应用中心第一版：租户应用页只展示 AgentCiCi 基础应用与 Semattice 业务数据与语义运行底座两张运营卡。页面不再把 AgentCiCi 的保留、导出、预演或销毁能力错误展示为租户共享能力；Semattice 仅展示受控开户契约已知事实，并提供 FEAT-134 的受控开通入口，不伪造尚未建模的许可证、到期、知识库或文档指标。

## 验收标准

1. 左侧导航覆盖所有上述叶节点，确实以路由拆分任务页面，而非给旧链接加分组标题。
2. 列表、详情/抽屉、编辑、版本与依赖不再永久堆叠在同一画布，原有功能均可完成。
3. `/platform` 首屏是待办、健康、最近变更、风险跟进的可操作入口。
4. 平台端可切换八主题，刷新后恢复平台账号偏好，且不会覆盖 Admin/用户端本地偏好。
5. 租户应用页在桌面端只展示应用中心；AgentCiCi 卡片可进入其独立生命周期路由，Semattice `company_id` 绑定和受控开户动作清晰可见。应用生命周期能力不以租户级共享区块出现，且不会把 Semattice 错述为知识库产品或虚构其运营数据。
6. 关键路由、二级展开、抽屉、筛选、编辑、保存和高风险确认在桌面端可用，无外层横向溢出和 console error/warning。
7. `cd frontend && npm run build`、相关前端测试、桌面截图检查和 `design-qa.md` 通过。

## 风险与回滚

- 复合页面拆分可能遗漏隐藏操作，必须按“功能保全对照”逐项迁移后再移除旧叠加视图。
- 共享主题函数若继续使用同一本地键会污染其他端未认证首屏；平台端只增加独立键，用户/Admin 行为不变。
- 回滚保留旧入口到新默认页的兼容跳转，不涉及数据或 API 回滚。
