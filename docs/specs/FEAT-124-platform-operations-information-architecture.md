# FEAT-124 - 运营管理端信息架构与独立主题重构

## 来源与已确认设计

- 用户指出现有 `/platform/*` 把策略编辑、版本历史、目录、详情和说明堆叠在同一页面，一级平铺菜单不足以支撑当前能力。
- 用户选择本会话 Product Design 的第 2 张「运营中枢」桌面稿，确认其以“待办优先队列 + 治理健康摘要 + 最近变更 + 风险跟进 + 右侧渐进式详情”为主结构。
- 用户明确二级菜单不是给旧菜单加分组，而是按功能拆出不同页面；不得改变、遗漏或混淆任何现有平台功能。
- 用户要求平台端拥有与用户/Admin 相同的八套受控主题，但平台账号的设置与本地回退均独立。

## 目标与非目标

### 目标

1. 平台运营人员先在总览判断待办，再通过二级任务页进入完整工作区。
2. 保留所有现有 `/platform/*` API、数据、权限、高风险确认和旧入口的兼容路径。
3. 列表页只承担搜索、筛选和扫描，低风险查看使用抽屉，配置/草稿/版本/发布/回滚使用独立路由。
4. 平台端复用受控八主题，但以独立账号同步和独立本地缓存键保存偏好。

### 非目标

- 不修改后端业务 API、数据库、权限模型、技能/模型/租户/计费事实或发布语义。
- 不新增移动端布局、移动端截图或移动端自动化测试。
- 不改变 `/platform/login` 已批准的像素锁定例外，也不改变 `/admin/*` 或用户端主题偏好。

## 目标信息架构

```text
总览
└── 运营总览                         /platform

能力治理
├── 技能目录                         /platform/skills
├── 策略与版本                       /platform/skills/policies
├── 依赖与影响                       /platform/skills/dependencies
├── 模型厂商                         /platform/models/providers
├── 运行模型目录                     /platform/models/catalog
├── 场景模型路由                     /platform/models/routes
├── 平台集成                         /platform/integrations
├── 工具目录                         /platform/tools
└── 工具治理                         /platform/tools/:toolName

运营管理
├── 套餐目录                         /platform/billing
├── 套餐版本编辑                     /platform/billing/editions/:editionCode
├── 加购包与 Credits                  /platform/billing/packages
├── 租户目录                         /platform/tenants
├── 租户生命周期                     /platform/tenants/:orgId
└── 注册与演示线索                   /platform/website-leads

风险与质量
├── 质量总览                         /platform/evaluation
├── 标准评测资产                     /platform/evaluation/suites
├── 运行洞察                         /platform/evaluation/runs
└── 平台审计                         /platform/audit

平台偏好
└── 界面主题                         /platform/preferences/appearance
```

旧的 `/platform/models`、`/platform/skills`、`/platform/tools`、`/platform/billing`、`/platform/evaluation` 保持为各自目录或总览页。原先混在页面内的 tab/选中状态改为可书签化子路由；租户详情、线索和审计入口保持现有路径。

## 页面与交互

### 运营总览

- 首位显示最多三条待办优先队列，每条都有影响范围、发生时间和唯一“处理”入口。
- 后续依次是紧凑治理健康、最近变更和风险跟进，均跳转到对应独立工作区。
- 低风险事项可在右侧抽屉中查看，不丢失上下文；抽屉中的“开始处理”必须进入完整页面，不在抽屉中编辑高风险配置。

### 目录、详情与编辑的边界

- 技能、工具、套餐、租户和评测资产目录页仅包含可筛选列表、少量扫描字段和三点行操作。
- 核心策略、技能模板、工具治理、套餐版本、包配置、模型厂商凭据、模型目录和场景路由均使用独立编辑页，并通过面包屑返回目录。
- 版本、依赖与影响范围不再常驻编辑器下方，而是“策略与版本”“依赖与影响”或对象详情内轻量 tab/子路由。
- 发布、回滚、销毁继续使用明确的 modal 确认和原有权限边界。

### 导航与主题

- 一级菜单只表达领域，二级菜单只表达可独立完成的任务。一级为可访问的 button，叶节点为 NavLink；当前领域、叶节点、展开和键盘焦点均有清晰语义。
- 平台偏好页展示既有八主题：鎏金账房、CRM 标准蓝、蓝色海洋、樱花粉语、熏衣紫语、牛油果小调、红酒醇香、星河幻境。
- 平台偏好通过既有平台账号端点同步，使用平台专属 localStorage 键；绝不读取、覆盖或写入用户/Admin 端的主题缓存。主题只映射 token，不改变菜单几何、控件尺寸、密度、图标、动画或滚动模式。

## 功能保全对照

| 现有能力 | 新工作区 | 保全要求 |
| --- | --- | --- |
| 标准技能、模板草稿、发布/回滚、核心策略、版本历史、依赖图 | 技能目录、策略与版本、依赖与影响 | 保留所有请求、版本判断和影响数据，只拆页面职责。 |
| 模型厂商、凭据检测、模型目录、场景路由 | 模型厂商、运行模型目录、场景模型路由 | 保留保存、检测、拉取、启停与清除路由操作。 |
| 平台集成、工具配置与依赖 | 平台集成、工具目录、工具治理 | 保留既有配置/保存流程。 |
| SaaS/私有化版本、容量/模块/服务包、Credits | 套餐目录、套餐版本编辑、加购包与 Credits | 保留部署筛选、版本保存、包保存和审计原因。 |
| 租户开通、保留、导出、预演、销毁 | 租户目录、租户生命周期 | 保留独立高风险确认与所有历史记录。 |
| 评测资产、用例、发布/归档、运行洞察 | 质量总览、标准评测资产、运行洞察 | 保留不可变版本、隐藏用例与发布门禁。 |
| 网站预约线索、平台审计 | 注册与演示线索、平台审计 | 路径、筛选、状态更新和脱敏展示不变。 |

## 技术范围与依赖

- 前端仅重构 `frontend/src/platform/**`、平台路由、平台作用域样式与主题偏好组件；必要时新增定向前端测试。
- 不复制业务逻辑，优先从现有复合页面抽取目录、详情、编辑视图以避免 API 行为漂移。
- 跨页面规则同步维护 `DESIGN.json`、`DESIGN.md`。
- TASK-218 当前独占 `PlatformModelsPage.tsx` 的厂商目录能力修复；本任务在其合并前不得编辑该文件，模型子路由拆分在该依赖解除后进行。

## 验收标准

1. 左侧导航覆盖所有上述叶节点，确实以路由拆分任务页面，而非给旧链接加分组标题。
2. 列表、详情/抽屉、编辑、版本与依赖不再永久堆叠在同一画布，原有功能均可完成。
3. `/platform` 首屏是待办、健康、最近变更、风险跟进的可操作入口。
4. 平台端可切换八主题，刷新后恢复平台账号偏好，且不会覆盖 Admin/用户端本地偏好。
5. 关键路由、二级展开、抽屉、筛选、编辑、保存和高风险确认在桌面端可用，无外层横向溢出和 console error/warning。
6. `cd frontend && npm run build`、相关前端测试、桌面截图检查和 `design-qa.md` 通过。

## 风险与回滚

- 复合页面拆分可能遗漏隐藏操作，必须按“功能保全对照”逐项迁移后再移除旧叠加视图。
- 共享主题函数若继续使用同一本地键会污染其他端未认证首屏；平台端只增加独立键，用户/Admin 行为不变。
- 回滚保留旧入口到新默认页的兼容跳转，不涉及数据或 API 回滚。
