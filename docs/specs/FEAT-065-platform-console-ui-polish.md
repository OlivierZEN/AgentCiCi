# FEAT-065 - 运营端前端页面 UI 整体美化

## 背景与目标

- 用户要求进入 goal 模式，检查所有运营端前端页面，并按项目规范的前端 UI 标准完成整体美化。
- 运营端范围是 `/platform/*` 产品控制面，用户是平台运营、平台管理员和平台审计人员。
- 目标是在不改变业务 API、数据结构和移动端范围的前提下，让运营端页面统一符合 `PRODUCT.md`、`DESIGN.md`、`DESIGN.json` 和 `鎏金账房` 产品 register。

## 范围

### In Scope

- `/platform/login`、`/platform`、`/platform/skills`、`/platform/models`、`/platform/integrations`、`/platform/tools`、`/platform/billing`、`/platform/tenants`、`/platform/tenants/:orgId`、`/platform/website-leads`、`/platform/audit` 的桌面端 UI 检查与修整。
- 平台外壳、导航、页头、统计、表格、文本 tab、按钮、表单、弹窗、能力标签、状态反馈与空状态的视觉一致性。
- 修复明确违反设计事实源的旧视觉模式：装饰渐变、旧蓝/青/紫标签、灰色弹窗体系、圆形图标按钮、厚侧边强调线、面板内卡片化和不一致按钮类。
- 本地构建与桌面浏览器截图检查。

### Out Of Scope

- 不新增移动端兼容实现、移动端布局适配、移动端截图或移动端自动化测试。
- 不改变后端接口、数据库、计费、权限和平台治理业务语义。
- 不处理非平台端 `/admin/*`、助手工作台、官网或帮助中心页面，除非它们被平台端复用且必须最小修正。

## 用户场景

- 平台运营人员在桌面显示器上长时间扫描治理状态、筛选审计记录、调整模型/集成/工具/计费配置。
- 平台管理员需要在高密度表格和详情面板之间快速切换，并能稳定识别当前选中项、风险状态和主操作。
- 平台审计人员需要可读、无横向溢出的审计表格和明确的筛选反馈。

## 现状与约束

- 已加载 `PRODUCT.md` 与 `DESIGN.md`，产品 register 为 `product`。
- `DESIGN.json` 要求运营端沿用暖象牙底、墨色文字、紧凑密度、香槟金结构线，产品面内 tab 和行操作以文本、下划线和字重表达状态。
- 代码审计发现模型页仍有旧灰色/蓝色/青色/紫色能力标签、圆形图标按钮和灰色编辑弹窗；平台登录主按钮使用渐变；网站注册页摘要区有超过 1px 的侧向强调感；部分保存按钮仍用通用 `primary` 类。
- 当前工作区已有 TASK-152/TASK-153/TASK-154 未提交改动；本任务必须避开无关后端和非平台实现。

## 方案设计

- 优先通过平台作用域 CSS 统一视觉语汇，减少逐页重写。
- 保留平台端熟悉的信息架构：左侧导航、页头统计、左表右详情、文本 tab、模态确认。
- 对模型页进行重点收口：供应商列表、模型目录、能力标签、场景路由和模型编辑弹窗统一到香槟金结构线与暖象牙表面。
- 对平台登录、计费、租户、审计和网站注册页做一致性修整，确保按钮类、表格、筛选、弹窗和状态文字符合设计事实源。

## 接口与数据影响

- 无后端 API、数据库、事件、配置或数据模型变化。
- 仅前端结构和样式调整；若局部 className 改动影响现有测试，需同步更新前端测试期望。

## 任务拆分

- `TASK-155`：运营端 UI 整体美化、桌面截图检查、构建验证和状态更新。

## 验收标准

- `/platform/*` 主要页面桌面端无明显旧蓝/青/紫视觉体系、装饰性渐变、厚侧边强调线、卡片套卡片或不一致按钮。
- 平台端 tab、行操作、表格、弹窗、筛选和按钮符合 `DESIGN.json` 中的产品 UI 标准。
- `cd frontend && npm run build` 通过。
- 本地桌面浏览器能登录平台端并完成关键页面截图检查；若某些接口数据为空或不可用，需要记录未验证风险。

## 风险与回滚

- 风险：当前工作区混有其他任务的未提交改动，视觉整改必须避免覆盖已有业务改动。
- 风险：部分平台页面复用 admin 组件，样式收口可能影响组织管理端；本任务尽量使用 `.platform-*` 或 `.platform-main .platform-page` 作用域。
- 回滚方式：回退本任务触碰的前端样式和平台端页面 className，不涉及数据迁移。
