# FEAT-103 - 客户互动档案、动态记忆与按需检索

## 目标

将原始材料、转写结果、AI 结构化分析、用户确认稿、客户动态记忆、助手依据和 CRM 行动串成可追溯闭环；助手不再每轮读取多年全量互动。

## 已确认产品方案

- AgentCiCi 保存原件、解析文本、AI 分析版本和客户记忆；CloudCC CRM 承接经确认的任务、风险、商机等业务动作。
- 原始证据不可覆盖；确认稿进入正式时间线；结构化事实进入客户动态记忆；助手按问题检索并引用证据。
- 互动确认只增量更新当前记录、当前客户记忆和受影响建议，不触发全客户或全历史重算。

## 数据设计

- 扩展正式互动事件：保存来源批次 ID、确认稿、结构化分析快照、分析版本和证据数量。
- 新增客户记忆项：组织、客户、来源事件、类型、内容、状态、置信度、发生时间、有效期、证据引用和更新时间。
- 记忆类型：`FACT / NEED / RISK / OPPORTUNITY / COMMITMENT / NEXT_ACTION / PENDING_QUESTION`。
- 状态：`ACTIVE / RESOLVED / SUPERSEDED`。同一来源重复确认保持幂等；重新分析新增版本，不覆盖历史证据。
- 原件继续存放在持久卷，数据库保存元数据、提取文本、SHA-256 和权限隔离路径。

## 检索与上下文策略

- 固定上下文：客户摘要、活跃商机、有效合同、未关闭个案、未完成任务和 CRM 连接状态。
- 近期窗口：默认最近 90 天且最多 20 条正式互动。
- 强制关注：未闭环风险、承诺、下一步行动和待确认问题，不受 90 天限制。
- 相关历史：按用户问题对记忆和互动做相关性、时间、状态混合排序，最多返回 8 条。
- 多年已关闭事项不进入默认上下文；用户明确询问历史时才扩大时间范围。
- 提示词只携带一次精简客户上下文，设置字符预算并输出证据编号；不得重复嵌套完整时间线。

## API 与界面

- `GET /customer-workbench/accounts/{accountId}/interaction-archive`：分页读取正式互动档案。
- `GET /customer-workbench/interaction-archive/{eventId}`：读取确认稿、AI 分析、原件和证据。
- `GET /customer-workbench/accounts/{accountId}/memory`：读取当前客户动态记忆。
- 时间线记录支持打开“互动档案”详情；详情以现有产品 tab 展示确认稿、AI 分析和原始材料。
- 右侧助手回复显示本轮使用的证据，点击后打开对应互动档案。
- 归集成功后提供“基于本次互动继续分析”，将来源事件作为本轮优先证据，不重新加载全量历史。

## 权限与边界

- 档案、原件、记忆和助手检索每次都校验当前用户对 CRM Account 的可见权限。
- 普通用户只能访问自己有权查看客户的档案；原始采集批次仍保留创建人编辑/重试边界。
- 不把原始敏感文件默认复制进 CRM；CRM 仅保存确认后的业务动作和可追溯引用。
- 本任务只做桌面产品面，不新增移动端实现。

## 验收标准

- 归集后可从时间线重新打开完整档案，查看确认稿、结构化分析和原件列表。
- 客户记忆由确认批次增量生成，未闭环项可跨时间窗口进入助手上下文。
- 普通提问的上下文最多 20 条近期互动、8 条相关证据且不包含重复完整客户 JSON。
- 生成待办默认排除多年已关闭任务；明确历史问题可以召回旧证据。
- 助手回复返回证据引用并可定位档案；无依据的推断继续标记待确认。
- 后端迁移、服务、权限和检索测试，前端交互测试、生产构建及真实桌面浏览器流程通过。
