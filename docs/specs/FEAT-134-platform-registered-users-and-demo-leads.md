# FEAT-134 平台端注册用户与演示线索拆分

## 目标

将运营管理菜单中的“注册与演示线索”拆为两个可独立访问的入口：

- **注册用户**：只展示尚未加入任一组织的系统个人账户。
- **演示线索**：承接现有官网预约演示列表、筛选与状态更新能力。

## 范围与边界

- 新增受平台角色保护的 `GET /platform/registered-users`，支持昵称、手机号和邮箱搜索，以及每页最多 100 条的分页。
- 个人账户的定义为 `user_account` 不存在任何 `organization_member` 关联；只要属于任一组织，就不在注册用户目录中返回。
- 新增 `/platform/registered-users` 和 `/platform/demo-leads` 前端路由；旧 `/platform/website-leads` 重定向到演示线索，避免既有书签失效。
- 不修改演示线索的数据来源、筛选、状态流转或写入行为。

## 验收标准

1. 运营管理下出现“注册用户”和“演示线索”两个菜单项。
2. 注册用户列表不返回任何组织成员账户，且可按昵称、手机号、邮箱查询和翻页。
3. 演示线索页面仍可查询并更新“待跟进 / 已联系 / 已关闭”状态。
4. 旧入口访问后落到新的演示线索页面。
