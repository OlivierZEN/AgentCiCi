# FEAT-172 - 运营控制台能力治理工作台重构

## 背景与问题

当前能力治理将“技能目录、策略与版本、依赖与影响、模型配置、平台集成、工具目录”作为同级菜单，但前三项都依赖当前技能上下文。技能目录、技能详情、版本和依赖又使用不同页面结构，运营人员需要重复选择对象并在页面间往返。现有主内容固定为窄列，右侧没有承载对象详情、风险和动作，导致桌面空间大量闲置。

第一版原型尝试用三栏常驻工作台消除空白，但用户评审确认该方案把目录、编辑、依赖、风险和动作同时堆入一个页面，形成新的信息拥挤。V2 改为渐进式披露后又错误扩大了改版范围，V3 随后恢复六个菜单与完整编辑页。最新评审确认前三个技能菜单仍可进一步合并为单一“技能治理”，技能版本与依赖影响作为当前技能的只读对象信息进入加宽速览抽屉；完整编辑和预览继续使用独立页面，任何功能字段与治理逻辑不得删减或改写。

## 本轮目标

- V1-V5 高保真 HTML 原型已完成评审；本阶段将用户确认的 V5 信息架构接入正式 React `/platform/*` 页面，并复用现有业务 API。
- 将“技能目录、策略与版本、依赖与影响”三个菜单合并为单一“技能治理”；能力治理侧栏最终保留“技能治理、模型配置、平台集成、工具目录”四项。
- “模型配置、平台集成、工具目录”的页面、路由和既有交互不在本轮调整范围内；原型只做冻结提示，不重新表现这些页面。
- 技能治理首页同时提供“技能列表”和“核心策略包”两个同层入口；默认展示技能列表，核心策略包不再藏在独立侧栏菜单中。核心策略包采用可扩展列表结构，当前仅 `core-default` 对应的“平台核心安全策略”可管理，数据出境、模型调用和工具执行策略仅作为明确的规划态方向展示。
- 技能列表只负责扫描、搜索、筛选与低风险行操作，不常驻编辑表单。
- 点击列表记录打开加宽右侧抽屉，抽屉通过“概览、技能版本、依赖与影响”三个页签承载当前技能的只读治理信息。
- 技能编辑恢复完整字段，并作为独立沉浸页面；治理设置、模板内容、能力边界、本版说明在编辑页内渐进切换，不与目录、版本或依赖混排。
- 核心策略包仍保留独立编辑页与草稿动作；技能草稿预览仍保留独立页面。
- 版本时间线、回滚点动作、Agent/工作流/历史版本引用、阻断项和发布检查必须完整保留在新交互中。

## 产品设计

### 信息架构

```text
能力治理
├── 技能治理（本轮重构）
│   ├── 技能列表（首页默认入口）
│   │   └── 加宽技能速览抽屉（概览 / 技能版本 / 依赖与影响）
│   ├── 核心策略包（首页同层入口） → 策略编辑
│   ├── 技能编辑（独立页面：治理设置 / 模板内容 / 能力边界 / 本版说明）
│   └── 草稿预览（独立页面）
├── 模型配置（冻结，保持现状）
├── 平台集成（冻结，保持现状）
└── 工具目录（冻结，保持现状）
```

### 渐进式页面层级

- 外层保留运营控制台壳层和平台账号上下文。
- 列表页使用完整主区域展示筛选器、标准表格、状态和单一主要动作；不保留无业务含义的右侧空白。
- 抽屉加宽到适合表格与双栏摘要的桌面宽度，只承载当前技能的只读概览、版本和依赖；关闭后回到原列表滚动与筛选状态，抽屉不放完整编辑表单。
- 编辑页隐藏列表，只呈现当前技能草稿；四类编辑内容通过页内步骤切换逐步展开，主操作固定为“保存为新草稿版本”。
- 版本页签呈现版本时间线、状态和草稿/回滚入口；依赖页签呈现引用关系和影响范围，二者都在加宽抽屉内按页签渐进展示。
- 预览页以只读方式展示将要生效的治理结果、变更差异和发布检查，不与编辑控件混排。
- 不使用营销式指标、装饰性渐变、玻璃拟态、嵌套卡片或无意义留白。

### 交互范围

- 侧栏“技能治理”进入统一首页；另外三个菜单只提示“保持现有页面，本原型不调整”。
- 首页支持“技能列表 / 核心策略包”切换；技能列表支持搜索、筛选和点击行打开抽屉。
- 抽屉支持概览、技能版本、依赖与影响三个只读页签；版本和依赖不再各占一个侧栏菜单或独立列表页。
- 独立技能编辑页支持四个内容步骤、保存草稿和预览；预览页只读展示差异与检查结果。
- 核心策略包入口先展示策略包列表；当前生效记录进入现有独立策略编辑页，保存策略草稿的逻辑与字段不变。规划态记录不得提供编辑、发布或伪造版本动作。
- 正式页面只呈现已有接口真实支持的保存、创建草稿、发布和回滚动作；不增加伪造的预检、创建或发布反馈。

## 非目标

- 本轮不修改后端、数据库、权限、API 或发布语义。
- 本轮不修改模型配置、平台集成和工具目录页面实现。
- 本轮不部署 UAT 或生产，不执行真实发布、回滚或 Secret 操作。
- 本轮不增加移动端适配或移动端验证。

## 原型验收

- `index.html` 可独立启动并在桌面浏览器访问。
- 主要导航、列表筛选、抽屉开关、独立页面进入/返回和原型动作可用。
- 在 1280×720 或更宽桌面视口中，主区域无明显空洞，无外层横向滚动。
- 页面遵循当前 CRM 标准蓝主题映射与 AgentCiCi 产品密度，不改变品牌体系。
- 完成浏览器全页截图检查、控制台错误检查和必要迭代。
