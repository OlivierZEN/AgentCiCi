# FEAT-105 - 互动驱动的客户经营动作

## 背景与目标

现有经营动作在客户详情首次打开时固定生成“创建下一次跟进任务”，并以“客户是否已有建议”作为永久阻断条件，不能响应持续发生的微信、邮件、电话、会议和客户反馈。

本次改为“互动分析识别动作候选 + 平台确定性治理 + 人工确认写回 CRM”。每次确认新的客户互动后，AI 从本次证据和当前 CRM 客户上下文识别可执行动作；平台负责校验、去重、生命周期和审计，模型不直接写 CRM。

## 业务规则

- 仅已确认互动触发动作生成；打开客户详情不再生成固定动作。
- AI 动作候选字段：动作类型、稳定业务键、标题、原因、证据、置信度、紧迫度、建议期限、有效期、目标记录。
- 支持 `CREATE_TASK`、`CREATE_OPPORTUNITY`、`UPDATE_OPPORTUNITY`。关系维护、续约、服务闭环和资料补充统一先落为可确认 Task；明确的新采购需求可创建 Opportunity；现有商机进展可更新 Opportunity。
- 置信度低于 `0.65`、没有原文证据、没有业务键或更新商机却缺少目标记录时，不生成动作。
- 同一客户、动作类型和业务键的未完成动作只保留一条；新证据可刷新待处理草稿。已采纳、已确认或执行中的动作不被模型覆盖。
- 已完成或已忽略动作允许在新的互动事件中再次生成，但七天内相同业务键进入冷却，避免重复提醒。
- 所有动作必须经过采纳、确认、写入 CRM；执行保持当前用户 CloudCC 身份和权限。

## 数据与接口

- V78 为 `customer_workbench_recommendation` 增加来源事件、来源批次、动作业务键、触发方式、有效期字段及查询索引。
- 互动分析 JSON 增加 `actionCandidates`；原有 `nextActions` 继续作为用户可读摘要，不直接写 CRM。
- 确认互动时在归档、记忆和动态评分后生成动作，并在返回结果中提供本次生成/刷新/跳过数量。
- 经营动作列表继续复用现有建议 API，新增来源事件、触发方式、有效期字段用于解释。

## UI

- 保留现有“老客户经营动作”结构、采纳/修改/忽略/确认/写入流程。
- 动作显示“互动识别”、来源时间和有效期；证据区继续跳转互动档案。
- 已过期动作不作为待处理动作计数，历史状态仍可在全部动作中审计。

## 验收标准

- 一次明确提出新采购需求的已确认互动可生成创建商机动作；同一事件重复确认不重复生成。
- 新的预算确认、方案评审、服务问题、续约或关系信号可生成相应跟进 Task 或商机更新动作。
- 无明确证据、低置信度和纯信息性沟通不生成动作。
- 同业务键的连续沟通不会堆积未完成动作；动作完成后出现新的独立证据可再次生成。
- 固定的首次打开客户建议逻辑被移除；已有历史动作保留且可继续执行。
- 聚焦后端测试、前端测试与构建、真实桌面浏览器、真实 CRM 权限写回和生产发布验收通过。

## 风险与回滚

- 模型输出漂移由严格 JSON 契约、白名单、置信度门槛、证据要求、冷却期和人工确认控制。
- V78 仅追加字段；回滚代码不会破坏已有建议，旧数据来源字段为空时按历史动作展示。

## 实现进展

- 2026-07-12：用户确认从固定补全建议升级为持续互动驱动的动态经营动作，进入实现。
- 2026-07-12：互动分析已增加 CRM 上下文和动作候选；平台完成原文证据校验、置信度门槛、业务键去重、七天冷却、历史时效校验、来源审计和人工确认写回。首次打开客户的固定建议逻辑及演示种子动作已移除。
- 2026-07-12：后端 24 项聚焦测试、前端 66 项测试与生产构建、本地桌面浏览器验收通过，进入生产发布。
