# FEAT-120 - 链路追踪全文查看与复制

## 背景与目标

- 组织管理员在“智能体运行”的链路追踪面板中只能看到节点摘要；用户输入等长文本带有省略号，无法在产品内核对完整上下文。
- 截图反馈确认此问题发生在客户互动工作台上下文等长文本场景，影响故障定位与回归用例判断。
- 本次交付让具备现有 Trace 查看权限的组织管理员按需展开、查看并复制脱敏后的完整字段，同时保留紧凑的默认监控密度。

## 范围

### In Scope

- Trace 详情 API 返回面向管理员显示的完整、脱敏后的请求与响应字段，且不破坏既有节点摘要。
- 节点的“展开全文”在侧栏内原位显示完整内容，并支持键盘操作与“复制内容”。
- 对历史 Trace 的已截断数据明确标识“该记录仅保留至 N 字”，不伪称全文。
- 新 Trace 的可查看文本按受控上限持久化，继续脱敏 token、密码、密钥和手机号等敏感内容。
- 前后端自动化测试及桌面端浏览器验收。

### Out Of Scope

- 不新增移动端布局或移动端验收。
- 不改变 Trace 的组织权限、留存时长、运行链路计算、模型调用或业务系统数据。
- 不向普通员工、跨组织用户或外部 API Key 扩大原文查看权限。

## 用户场景

- 组织管理员在 `/admin/ops` 选中运行记录，发现“用户输入”或模型/工具结果以省略号结束。
- 点击“展开全文”后，当前节点原位展开可滚动、可选中的预格式化内容；点击“收起”恢复监控密度；复制操作给出非侵入式成功反馈。
- 历史记录若已在旧版本截断，界面展示实际保存的内容和保留上限提示，避免误导排障。

## 方案设计

- 保持“鎏金账房”认证后管理界面的暖象牙、墨色、香槟金结构线和紧凑工作台语气；不引入新卡片、弹窗或视觉 token。
- 默认节点继续只呈现摘要，避免长上下文挤占整条链路。全文采用节点内的渐进披露，按钮为文本命令，配合 `aria-expanded` 和明确的复制结果状态。
- 服务端区分节点摘要和管理员详情：摘要维持短文本，详情字段保存经过统一脱敏后的可查看内容。API 仅在已有 `@RequireOrgAdmin` 的详情接口中返回管理员详情。
- 因截图内的 CRM 上下文本身可能含业务数据，复制内容仍沿用管理员权限和服务端脱敏规则；不把全文写入列表接口、标题或日志摘要。

## 接口与数据影响

- 扩展 `GET /admin/agents/run-logs/{traceId}` 的 `detail` 数据，加入管理员可查看的 Trace 文本及截断/保留元数据。
- 不修改列表接口、数据库表结构或既有 Trace 节点 JSON 的读取兼容性。
- 对新写入 Trace，详情可查看文本上限设为受控值；旧 Trace 无法恢复存储前已丢失的原文。

## 任务拆分

- `TASK-215`：后端详情持久化与脱敏、前端展开/复制交互、测试和桌面端验证。

## 验收标准

- 管理员在 Trace 节点可查看并复制受控详情，不再只能依赖省略号摘要。
- 默认态保持链路列表紧凑；展开、收起、复制、键盘焦点、复制失败和历史截断提示均可用。
- 非管理员接口和运行日志列表不返回新增完整文本。
- 相关后端测试、前端测试、生产构建、桌面端浏览器截图与交互检查通过。

## 风险与回滚

- 风险：Trace 原文可能包含敏感业务字段。通过现有组织管理员权限、统一脱敏和受控长度降低暴露面。
- 回滚：前端可回退为仅摘要显示；后端新增详情字段为兼容性扩展，不影响旧客户端读取。
