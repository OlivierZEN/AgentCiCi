# FEAT-113 - 前台主题一致性与视觉对齐全量治理

## 背景与目标

用户提供的真实页面截图表明，账号主题已经能改变助手壳层画布，但多个前台页面、AI 应用、弹窗和空态仍保留历史鎏金、蓝色、橙色或固定浅色，形成“外层已换主题、内层仍是旧主题”的割裂。部分工具栏、表单列、卡片内容和列表元素还存在基线不齐、间距不一致、左右边界参差的问题。左下角组织切换入口固定显示 `CB`，也不能表达当前组织。

本任务以认证后的普通用户前台 `/app` 为范围，完成一次逐页主题和对齐治理：所有页面继续共享同一结构、密度和交互，只通过八套受控语义 token 改变颜色；组织入口使用当前组织名称首字符；逐页修复可见错位、溢出和不一致控件。

## 产品与视觉方向

- 使用者：日常在助手工作台切换智能体、AI 应用、客户工作台和个人设置的企业员工。
- 场景：白天办公显示器上的连续业务操作，需要低疲劳、快速扫描和稳定位置记忆。
- 语气：克制、可信、紧凑；不把主题切换变成页面重构或装饰效果。
- 差异化方向：八套主题共享同一“企业工作台骨架”，差异只来自画布、表面、文字、结构线、强调色、状态色和图表序列色。

## 范围

### In Scope

- 助手壳层：一级轨道、组织菜单、智能体列表、会话区、空态、输入区、AI 应用选择菜单。
- 前台业务页：客户互动工作台、数据洞察、知微画像、客户洞察、智能体工作区及其可见详情状态。
- 个人设置与弹层：专属记忆、个人工作流、沟通渠道、邮箱、界面主题，以及前台业务流程触发的 modal、drawer、popover。
- 八套主题：`gilded`、`crm-blue`、`ocean`、`sakura`、`lavender`、`avocado`、`wine`、`galaxy`。
- 将当前主题未覆盖的固定颜色改为语义 token；为数据图表补充受控序列色，不允许组件直接写死外部品牌色。
- 修复标题、工具栏、筛选器、表单控件、表格单元格、列表行、卡片内容和弹窗分栏的对齐与间距问题。
- 左下角组织切换入口显示当前组织名称的首个有效字符：中文取首字，拉丁字母转大写；名称为空时显示“组”。
- 新增静态与行为测试，完成真实桌面端逐页截图和交互验收。

### Out of Scope

- 不修改 `/admin/*`、`/platform/*`、营销站和登录页的页面结构。
- 不改变主题目录、主题账号级持久化契约、业务 API、数据结构和权限逻辑。
- 不新增任意颜色、自定义 CSS、位图背景、主题专属布局、移动端适配或移动端测试。
- 不重写业务模块，不借视觉治理修改业务流程。

## 统一主题设计

### 语义 token

- 所有前台模块使用 `--theme-canvas`、`--theme-surface*`、`--theme-text*`、`--theme-line*`、`--theme-accent*`、`--theme-success*`、`--theme-warning*`、`--theme-danger*`。
- 新增四个受控图表/身份序列色 `--theme-data-1` 至 `--theme-data-4`，每套主题提供可读且同风格的序列；深色主题单独保证对比度。
- 模块可以用局部别名表达业务含义，但别名必须映射到公共主题 token，不能继续保留固定金、蓝、紫、橙、粉或纯白背景。
- 遮罩、焦点、禁用和状态继续使用公共语义 token，主题切换不得引起尺寸、阴影、位移或布局变化。

### 组织入口

- 新增纯函数 `getOrganizationMonogram(name: string): string`。
- 先 `trim()`；空值返回“组”；首字符若为拉丁字母则转为大写，中文、数字和其他可显示字符原样返回。
- 轨道入口的 `aria-label` 继续包含完整当前组织名称，视觉只显示单字符，不显示 `CB`、组织 ID 或缩写猜测。
- 切换组织后直接根据新的 `currentOrgName` 重算，不新增持久化字段。

## 页面布局与对齐规则

- 同一工具栏内标题、标签、筛选器和按钮采用统一纵向中心线；紧凑控件高度保持 32 至 34px。
- 同组表单标签基线一致，输入框、选择器和日期控件顶部/底部对齐；双栏弹窗的分栏线、标题区、正文区和页脚边界连续。
- 列表与表格保持列头和内容同一水平锚点；头像、名称、标签、状态和操作在行内垂直居中，不通过任意 margin 微调单个元素。
- 卡片组使用统一行高和内边距；内容高度不同也不改变同一行的顶部基线。
- 空态内容在可用内容区域内几何居中，不相对整个浏览器或被侧栏挤偏。
- 菜单、popover 和 modal 使用不透明主题表面、主题结构线与统一圆角；不得残留默认主题边框或第二层卡片背景。
- 所有页面保持无横向溢出，文字截断和换行不挤压操作列。

## 前台验收矩阵

1. 助手会话与智能体工作区：系统/已发布智能体列表、空会话、已有会话、搜索与选中态。
2. AI 应用入口：菜单默认/hover/focus/打开状态以及客户互动工作台、数据洞察、知微画像、客户洞察。
3. 客户互动工作台：新客/老客、列表、详情、整理互动记录弹窗、AI 助理侧栏。
4. 数据洞察：销售业绩、客户、商机、订单回款四个视图，图表、指标、表格和空白区域。
5. 知微画像：对象列表、画像详情、标签库、AI 配置、运营看板。
6. 个人设置：工作流、沟通渠道、邮箱、专属记忆、界面主题及其空态/表单态。
7. 跨页面公共状态：modal、drawer、popover、menu、toast、loading、empty、error、disabled。

## 测试与验收

- 先增加失败测试，锁定组织首字符规则、公共数据序列 token 和重点模块主题选择器覆盖。
- 前端全量 Vitest、TypeScript/Vite 生产构建和 `git diff --check` 必须通过。
- 真实浏览器至少以 `gilded`、`sakura`、`galaxy` 逐页检查全部前台验收矩阵；助手壳层和主题设置额外完成八主题快速矩阵。
- 对每个页面检查画布/表面/文字/边框/强调色、标题与控件基线、列对齐、弹窗分栏、菜单位置、空态居中、水平溢出和 console。
- 最终桌面端截图必须覆盖用户指出的七类问题页面；浏览器 console error/warning 为 0。

## 风险与回滚

- 风险：宽泛主题覆盖误把透明结构层重新绘制成卡片。修复必须以具体可视组件为单位，结构 wrapper 保持透明。
- 风险：图表色完全使用单一强调色导致系列难以区分。使用受控 `data-1..4`，同时保持不同主题内的明度和色相可区分。
- 风险：全局选择器优先级过高影响管理端或平台端。新增选择器必须锚定 `.cici-app` 或明确前台模块根节点。
- 回滚：撤回 FEAT-113 前端和 DESIGN.json 提交即可；无 API、数据库和用户数据回滚。

## 用户决策

- 用户明确要求直接实现，不再逐项询问。
- 采用统一语义 token 与页面专项对齐相结合的方案，不通过单一全局 `!important` 覆盖全部组件。
- 组织入口使用组织名称首字符，不使用 `CB`。
