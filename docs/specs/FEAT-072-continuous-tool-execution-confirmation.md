# FEAT-072 - 连续确认后的工具任务续执行

## 背景

线上 `2.1.5` 中，用户先问“看下今天的邮件”，助手列出今日邮件并询问“需要展开正文吗？”。用户回复“是的”后，助手只输出“已找到邮件，让我读取正文内容。”，没有实际调用 `email_get_message`，导致会话看起来已经结束但任务没有完成。

## 目标

- 当上一轮工具已找到唯一待展开邮件，用户下一轮用“是的/好的/继续/展开/读取”等确认语回复时，后端必须继续执行正文读取工具，而不是只生成承诺文本。
- 将待展开邮件 `messageId` 写入会话状态，供下一轮确认使用。
- 在流式与非流式对话路径中都支持该续执行。
- 防止最终回答出现“让我读取/我来查看”等未完成承诺后直接结束。

## 范围

- `ChatSessionStateService` 记录 `email_search` 唯一命中的待展开 `messageId`，并在 `email_get_message` 完成后清除。
- `ChatOrchestratorService` 在用户确认上一轮待展开邮件时，确定性补发 `email_get_message` 工具调用，并把工具结果加入本轮消息上下文。
- 补充 focused 单元测试覆盖确认意图、待展开邮件状态解析和“让我读取正文”类承诺识别。

## 非目标

- 不修改邮件 POP3/SMTP 协议和真实账号配置。
- 不改前端视觉或聊天布局。
- 不引入通用工作流引擎；本次只修复邮件正文续执行的生产缺陷。

## 验收标准

- 用户先“看下今天的邮件”，助手列出唯一邮件并询问是否展开；用户回复“是的”后，系统实际调用 `email_get_message` 并输出正文，而不是只说“让我读取”。
- 如果没有待展开邮件或命中多封邮件，确认语不会误触发读取。
- 本地 focused backend tests、backend compile、static check 通过。
