# FEAT-153 - 研发交付创建意图的大模型语义理解

## 背景与问题

- 用户输入“帮我创建一个新项目：AgentCiCi企业级智能体平台”时，系统把项目名称截成“新”。
- 已验证根因是创建草案由服务端正则直接抽取名称并生成答案，绕过了大模型；继续增加正则不能覆盖自然语言的表达变化，也不符合 AI 原生产品定位。
- 创建确认后的 Semattice 写入门禁是正确的，必须保留。

## 产品目标

- 创建项目、需求或任务的自然语言请求先由当前智能体模型理解完整语义，再生成结构化草案。
- 模型需要从整句话和会话上下文判断对象类型、完整名称或标题、父项目/父需求；不得按固定词位截取。
- 只有用户发送精确确认指令后，服务端才允许使用当前成员 OACT 写入同租户 Semattice。

## 范围

### In Scope

- 将未确认创建请求从确定性正则答复改为模型生成答复。
- 服务端仅做宽泛的“创建类请求”路由，不从文本中抽取项目名、需求标题或任务标题。
- 为模型注入本轮专用创建草案契约，禁止调用工具和声称已创建，并输出可复制的精确确认指令。
- 保留确认消息的确定性解析、权限检查、Semattice 写入和实际回执。
- 增加截图原句与常见表达的定向回归，并在生产以真实模型在线验证。

### Out Of Scope

- 不把 Semattice 写工具暴露给模型自由调用。
- 不改变元数据、字段模型、租户映射、OACT 或独立 DEV Autopilot 应用。
- 不在本任务扩展更新、删除、工时登记或变更审批能力。

## 交互与编排设计

1. 当前研发交付产品经理收到用户消息。
2. 服务端确认智能体身份、创建能力授权，并宽泛识别本轮是否属于项目/需求/任务创建；该步骤不抽取业务字段。
3. 未确认创建请求追加专用系统指令，并禁用本轮工具调用，由大模型阅读完整用户消息和既有会话后生成草案。
4. 模型能确定信息时返回完整对象名称、初始默认值和精确确认文本；不能确定时只追问缺失信息，不臆造。
5. 用户发送精确确认消息后，服务端解析确认载荷，合成内部写入调用，以当前用户 OACT 写入 Semattice，并返回真实编号。

项目草案的关键输出契约：

```text
我理解你要创建一个研发项目。
拟创建项目：<完整项目名称>
初始状态：规划中 | 健康度：待评估 | 进度：0% | 版本：v0.1.0
确认无误后，请回复：确认创建项目：<完整项目名称>
```

## 安全边界

- 模型生成的草案永远不是写入授权，也不得产生“已创建”表述。
- 只有精确确认语法进入服务端确定性写入路径；未确认消息使用空工具集调用模型。
- 公司、成员和访问令牌仍只来自当前服务端会话，用户文本与模型输出不能覆盖租户身份。
- 写入失败或父记录不唯一时保持失败不写入，并返回 Semattice 真实错误语义。

## 验收标准

- 截图原句“帮我创建一个新项目：AgentCiCi企业级智能体平台”由真实模型返回完整名称 `AgentCiCi企业级智能体平台`，不得返回“新”。
- “现在创建一个研发项目名称叫：AgentCiCi企业级智能体平台”等表达同样保留完整名称。
- 未确认请求不写入 Semattice，响应运行信息显示真实模型而不是服务端固定答复。
- 精确确认写入路径、同租户 OACT、工具审计和真实回执回归通过。
- 定向 JUnit、后端编译、发布检查、生产健康检查和在线对话验证通过。

## 发布与回滚

- 以 AgentCiCi 下一修订版本发布 backend；frontend 无业务改动时仍沿用统一版本镜像流程。
- 若模型草案链路异常，回滚应用镜像；不得通过恢复正则字段提取绕开模型。

## 实现进展

- 未确认创建消息不再由 `draftResponse` 或项目名正则生成答案；服务端只宽泛识别创建候选，不抽取业务字段。
- 阻塞和流式聊天均在创建草案轮次追加模型专用语义契约、跳过实时事实查询并禁用工具，最终答复由当前智能体模型生成。
- 精确确认仍由服务端解析并合成内部 Semattice 写入，写工具没有进入模型 function schema。
- 定向 JUnit、聊天编排回归、后端 package 和静态差异检查已通过；生产发布与真实模型验证待完成。
