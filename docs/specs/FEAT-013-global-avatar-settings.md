# FEAT-013 - Global Avatar Settings For Agents And Current User

## 背景与目标

- 当前产品已经在多个位置展示头像：前台 rail、消息气泡、智能体切换条、会话详情、管理端用户页等，但头像来源不统一。
- 用户头像已有 `app_user.avatar_base64` 字段和管理端头像上传能力，但“当前登录用户自己设置头像”的前台入口尚未成型。
- 智能体定义目前只有名称、摘要、欢迎语、模型等字段，缺少可由管理员维护并在前台全局展示的头像字段。
- 本功能目标是建立一套轻量、可复用、权限清晰的头像设置机制：管理员维护智能体头像，当前登录用户只维护自己的头像，系统中所有需要展示智能体或当前用户身份的位置都统一读取对应头像。

## 范围

### In Scope

- 在智能体定义中增加头像配置能力，仅组织管理员可在管理端 Agent Builder 中设置。
- 在前台个人设置入口中增加“我的头像”设置，仅当前登录用户本人可修改自己的头像。
- 第一版头像来源采用本地图片上传、前端方形裁剪、压缩为较小 data URL，再提交后端保存。
- 统一前端头像展示组件或头像解析函数，覆盖系统中所有智能体头像、当前登录用户头像、外部会话参与人头像展示点。
- 明确头像展示映射：智能体身份展示使用 `agent.avatarBase64`；当前登录用户身份展示使用 `/auth/me.avatarBase64`；外部渠道参与人展示继续优先使用会话 payload 的 `avatarUrl`。
- 保留默认字母头像兜底：无图片时显示智能体名称首字或用户昵称/手机号尾号。
- 后端对头像字段做基础安全与体积校验，避免提交超大 base64。

### Out Of Scope

- 不做 AI 生成头像。
- 不做头像库、预设形象市场或多头像历史版本。
- 不做对象存储、CDN、图片审核流、裁剪 UI 的复杂拖拽编辑器。
- 不允许员工修改智能体头像。
- 不允许组织管理员在本功能中替用户设置前台自助头像；现有管理端用户头像维护是否保留，作为历史管理能力暂不扩大范围。

## 用户场景

- 组织管理员在 `/admin/agent-builder/:agentId` 编辑智能体时，为不同业务智能体设置稳定头像，让员工在工作台中更容易区分“思思”“售前跟进 Agent”“审批推进 Agent”等角色。
- 员工用户在前台左侧 rail 点击个人头像进入个人设置，上传或更换自己的头像，保存后 rail、消息气泡和新会话参与人身份立即更新。
- 新租户或新智能体尚未设置头像时，系统继续显示名称首字兜底，不阻塞会话、发布和调试流程。
- 上传失败、格式不支持或图片过大时，用户在当前设置区域看到内联错误，不丢失原头像。

## 设计 Brief

### 1. Feature Summary

这是一套跨前台与管理端的头像配置能力，服务两个高频识别场景：员工需要在工作台快速区分“我”和当前智能体，管理员需要让不同智能体在列表、会话和消息中保持一致身份。它不是社交化装扮功能，而是产品工作台里的身份识别基础设施；一旦头像被设置，所有对应身份出现的位置都必须同步显示。

### 2. Primary User Action

用户最重要的动作是“选择一张图片并保存为当前头像”。管理员完成后，智能体头像全局生效；员工完成后，仅自己的前台头像全局生效。

### 3. Design Direction

- Color strategy：Restrained。沿用 `鎏金账房`，暖象牙底、墨色文字、香槟金边框与 focus 态，头像图片本身可以带来色彩，但外框和操作控件保持克制。
- Theme scene sentence：组织管理员和员工在白天办公环境中快速完成身份设置，心态是任务导向而非装饰探索，界面需要明确、轻量、保存反馈可靠。
- Anchor references：Linear 的设置密度、Stripe Dashboard 的表单清晰度、macOS Contacts 的头像裁剪直觉。
- Per-surface rule：前台个人设置更轻、更像抽屉/侧 panel 内的个人资料区；管理端 Agent Builder 更高密度，嵌入已有“定义”编辑节奏。

### 4. Scope

- Fidelity：production-ready design brief，下一步可直接实现。
- Breadth：一个全局头像能力，包含后端字段/API、管理端智能体设置、前台当前用户设置和全系统展示统一。
- Interactivity：上传、预览、清除、保存、错误反馈、保存后即时刷新。
- Time intent：先交付稳定 MVP，再按需要扩展对象存储或头像库。

### 5. Layout Strategy

- 管理端 Agent Builder：在“定义/基础信息”区域靠近智能体名称放置头像设置，采用“小头像预览 + 上传按钮 + 清除按钮 + 说明文字”的紧凑横向结构。它应是身份字段的一部分，不单独做大卡片。
- 前台个人设置：在当前个人设置入口顶部增加个人资料段，头像作为第一视觉锚点，下方保留现有邮箱等个人配置能力。用户点击 rail 头像后进入同一设置面板，不新增全屏页面。
- 全局展示：所有头像都通过统一组件渲染，图片头像优先，字母兜底次之。头像外框使用 1px 金线或暖色边界，active/focus 状态用香槟金 ring，不使用大面积金色填充。
- 展示一致性：同一身份在不同尺寸下只改变尺寸和边界密度，不改变来源。例如 `思思` 在智能体切换条、消息气泡、状态卡和档案卡中都使用同一张智能体头像。

### 6. Key States

- Default：展示当前头像或字母兜底，旁边有“上传头像”“清除头像”。
- Previewing：选择图片后立即显示本地裁剪压缩预览，保存前明确为未保存状态。
- Saving：保存按钮进入 loading/disabled，保留预览，不闪烁回旧头像。
- Success：内联提示“头像已更新”，前台 rail 和消息头像立即刷新。
- Propagated display：保存成功后，所有已挂载的头像展示点即时刷新；后续重新加载页面也从后端字段恢复同一头像。
- Error：格式不支持、体积过大、网络失败、后端校验失败均在头像区域内联展示。
- Empty fallback：无头像时显示智能体名称首字或用户昵称/手机号尾号。
- Readonly boundary：员工在前台看不到智能体头像编辑入口；管理员在 Agent Builder 看不到“替当前员工设置个人头像”的入口。

### 7. Interaction Model

- 点击上传后选择本地图片，前端读取图片，中心裁剪为正方形，压缩到 256x256 WebP data URL。
- 点击保存后提交后端；成功后用接口返回值更新本地状态，刷新相关列表/详情中的头像。
- 点击清除头像后先进入预览态，用户保存后才真正清空后端字段。
- 键盘访问需要可用：上传控件、清除按钮、保存按钮都有清晰 focus ring 和可读 label。
- 不使用 modal 作为第一交互；优先在现有设置 panel 或 Agent Builder 表单中内联完成。

### 8. Content Requirements

- 智能体设置区标题：`智能体头像`
- 智能体说明：`用于工作台、会话消息和智能体档案展示。仅管理员可修改。`
- 用户设置区标题：`我的头像`
- 用户说明：`用于前台工作台和消息气泡，仅你本人可修改。`
- 上传按钮：`上传图片`
- 清除按钮：`清除头像`
- 保存按钮：`保存头像`
- 错误文案：
  - `请选择 JPG、PNG 或 WebP 图片`
  - `图片过大，请选择 5MB 以内的图片`
  - `头像保存失败，请稍后重试`
  - `头像数据过大，请重新选择图片`

### 9. Recommended References

- `reference/product.md`：保持产品面熟悉、稳定、低装饰。
- `reference/interaction-design.md`：处理上传、保存、错误反馈和即时刷新。
- `reference/layout.md`：把头像设置嵌入现有表单而不是制造新卡片。
- `reference/color-and-contrast.md`：确保头像外框、focus ring、错误提示满足可读性。

### 10. Open Questions

- 现有管理端用户管理里的管理员代设用户头像是否需要保留、隐藏或后续迁移为只读展示。本轮设计按“不扩大范围”处理，不主动删除历史能力。
- 是否需要对已发布 Agent 的头像做版本快照。第一版建议不进入 publish version，头像作为当前展示资料实时生效；若未来渠道发布需要稳定形象，再单独建版本化策略。

## 方案设计

### 数据模型

- 复用 `app_user.avatar_base64` 作为当前用户头像字段。
- 新增 `agent_definition.avatar_base64 TEXT`，存储智能体头像 data URL。
- 后端返回字段统一命名为 `avatarBase64`，前端展示层不直接关心字段来自用户还是智能体。
- 第一版继续使用数据库 text 字段，后续如迁移对象存储，可新增 `avatar_asset_id/avatar_url` 并保留兼容读取。

### API 设计

- `GET /auth/me`：继续返回当前用户 `avatarBase64`。
- 新增 `PUT /auth/me/avatar`：当前登录用户更新自己的头像。
- `GET /agents`、`GET /agents/{agentId}`：返回智能体 `avatarBase64`。
- `PUT /agents/{agentId}` 或新增 `PUT /agents/{agentId}/avatar`：管理员更新智能体头像。建议第一版若改动小，可随定义保存；若要减少草稿保存耦合，则单独 avatar API 更清晰。
- 所有写接口限制头像 data URL 类型和长度，推荐后端上限约 200KB，前端上传源文件上限 5MB。

### 前端结构

- 新增或抽取 `AvatarView`：接收 `src`、`fallbackText`、`size`、`tone`，统一图片裁切、兜底字母、金线边界和 aria label。
- 新增或抽取 `processAvatarFile(file)`：复用现有管理端用户页的 256x256 WebP 压缩逻辑。
- Agent Builder 的 `AgentDraft` / `AgentRecord` / `AgentApiRecord` 增加 `avatarBase64`，保存时带上或调用 avatar API。
- Assistant Workbench 的 `PublishedAgentPayload` / `WorkbenchDockAgent` 增加 `avatarBase64`，智能体切换条、消息气泡、状态卡、智能体档案全部统一读取。
- 前台个人设置入口在现有 rail avatar 打开的设置面板中加入当前用户头像设置，保存成功后刷新 `me` 并更新 rail 与消息气泡。

### 展示覆盖矩阵

#### 智能体头像

- 管理端 Agent Builder：智能体列表项、编辑页基础信息头像预览、当前选中智能体标题区。
- 前台工作台：顶部智能体切换 chip、工作台消息流中的 assistant 消息头像、右侧/侧栏状态卡头像、监控卡片头像。
- 前台会话页：左侧智能体卡片、会话列表上方当前智能体标识、聊天头部智能体头像、assistant 消息头像、右侧智能体档案卡。
- 未来新增的 Agent picker、Agent detail、runtime/debug 面板中只要展示智能体身份，也必须使用同一 `avatarBase64` 解析规则。

#### 当前登录用户头像

- 前台左侧 rail 个人入口。
- 前台工作台用户消息气泡头像。
- 前台会话页用户消息气泡头像。
- 前台个人设置面板顶部资料区头像预览。
- 管理端 `AdminShell` 当前登录用户区域如果展示的是当前本人，也应读取 `/auth/me.avatarBase64`；管理端用户列表中的其他用户头像不属于“当前登录用户自助头像”展示，但可继续展示已存在的用户头像字段。

#### 外部会话参与人头像

- 会话线程列表和会话对象卡继续优先使用后端会话 payload 中的 `avatarUrl`，例如飞书绑定用户头像。
- 如果外部参与人没有 `avatarUrl`，继续用参与人名称首字兜底，不使用当前登录用户头像或智能体头像。
- 外部参与人的头像来源不在本轮设置范围内，只纳入统一 `AvatarView` 展示规则。

### 头像解析优先级

- `agent`：`agent.avatarBase64` -> 智能体名称首字兜底 -> `agentId` 首字兜底。
- `currentUser`：`me.avatarBase64` -> 昵称首字 -> 手机号尾号 -> `我`。
- `participant`：`thread.avatarUrl` -> 参与人名称前两字 -> `会`。
- `adminCurrentUser`：`/auth/me.avatarBase64` -> 昵称首字 -> 手机号尾号 -> `我`。

### 权限边界

- 智能体头像：仅 `ORG_ADMIN` 或更高权限的管理端入口可改。
- 当前用户头像：任何已登录用户只能改自己的头像。
- 管理员不能通过前台个人设置改他人头像；员工不能通过前台或会话工作台修改智能体头像。
- 后端必须按租户校验 `agent_definition.org_id` 和 `app_user.org_id`。

## 接口与数据影响

- 新增数据库迁移：`agent_definition.avatar_base64 TEXT`。
- 可能新增当前用户头像更新接口，不影响登录 token 格式。
- 现有 `app_user.avatar_base64` 保持兼容，不迁移历史数据。
- 如果采用单独智能体头像 API，不影响现有 Agent 定义保存 payload；如果随 `PUT /agents/{agentId}` 保存，需要保证旧前端不传字段时不会清空头像。

## 验收标准

- 管理员能在 Agent Builder 为智能体上传、预览、保存和清除头像。
- 员工能在前台个人设置中上传、预览、保存和清除自己的头像。
- 保存后的智能体头像在前台智能体切换条、工作台消息、状态卡、智能体档案中一致展示。
- 保存后的用户头像在前台 rail、用户消息气泡和新建工作台会话参与人中一致展示。
- 展示覆盖矩阵中的每个头像位置都使用对应身份头像：智能体用智能体头像，当前登录用户用本人头像，外部参与人用渠道 `avatarUrl` 或参与人兜底。
- 同一身份在不同页面和组件中的头像保持一致，不出现部分位置仍显示旧的渐变字母块。
- 无头像时仍稳定显示字母兜底，不出现破图、空白圆或布局跳动。
- 员工无法修改智能体头像；用户无法修改其他用户头像；跨租户数据不可访问。
- 图片格式、源文件大小、data URL 长度异常时有明确内联错误。
- `frontend npm run build` 通过，后端相关集成测试通过。

## 风险与回滚

- 风险：base64 存库会增加响应体积。控制方式是前端强制 256x256 WebP 压缩，后端限制长度；头像字段只用于列表和详情必要返回。
- 风险：旧接口保存定义时误清空头像。控制方式是更新命令对 null 和空字符串语义分离，或采用单独 avatar API。
- 风险：头像展示点散落，容易漏改。控制方式是先抽统一组件/函数，再替换主要入口。
- 回滚方式：保留字段但停止写入，前端回到字母兜底；已有头像数据不会影响运行时聊天逻辑。
