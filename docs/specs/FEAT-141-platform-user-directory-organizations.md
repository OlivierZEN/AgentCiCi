# FEAT-141 - 平台注册用户目录的组织归属展示

## 背景与目标

运营管理端已将“注册用户”定义为全平台个人账户目录，但运营人员还需要直接知道每个账户当前加入了哪些组织。一个账户可以属于多个组织，目录仍必须以账户为唯一行，不得因成员关系出现重复记录。

## 范围

### In Scope

- 扩展 `GET /platform/registered-users` 响应，为每个账户附带当前有效组织的 ID 与名称。
- 以 `user_account` 分页结果作为唯一行源，再批量读取其有效 `company_member` 关系，避免逐行查询。
- 表格新增“已加入组织”列：显示该账户的全部当前有效组织名称；没有组织时显示“未加入组织”。
- 保持既有搜索、分页、平台角色鉴权与“一账户一行”语义。
- 增加后端与前端定向回归，覆盖零、一个、多个组织和重复成员数据的聚合。

### Out Of Scope

- 不显示成员角色、成员状态历史、组织内其他成员或组织详情链接。
- 不修改注册、邀请、成员关系、权限、数据库 schema、移动端布局或生产环境。
- 不改变主题、token、组件语汇或跨页交互，因此不更新 `DESIGN.md` / `DESIGN.json`。

## 用户场景

- 平台运营人员在一张目录表中检索全部个人账户，并立即看到每个人当前归属的组织。
- 用户未加入组织时，组织列清楚显示“未加入组织”。
- 用户当前加入多个组织时，同一行完整列出多个组织名称，而不是生成多行记录。

## 方案设计

- 账户分页继续只查询 `user_account`，确保 `total` 和表格行数按账户而非成员关系计算。
- 服务层收集当前页账户 ID，用一次 `IN` 查询读取 `ACTIVE` 的 `company_member` 记录；按账户 ID 分组，并以组织 ID 去重。
- 接口增加 `organizations: [{ id, name }]`；空数组表示当前没有有效组织关系。
- 前端在现有语义表格中新增一列，用中文顿号显示组织名称并提供完整 `title` / 无障碍标签；不截断组织列表，不增加横向滚动或额外卡片。

## 接口与数据影响

- 路径、鉴权及查询参数不变：`GET /platform/registered-users` 仍要求平台角色。
- 响应项新增只读 `organizations` 字段，是向后兼容的数据扩展。
- 只读取当前有效成员关系；已退出或失效的历史成员关系不属于“当前已加入组织”。
- 不涉及迁移、写入或缓存失效。

## 验收标准

- 全平台账户继续全部出现，且同一账户只显示一行。
- 零组织账户返回空 `organizations` 并在界面显示“未加入组织”。
- 单组织与多组织账户返回、显示全部当前有效组织名称；重复成员记录不会重复显示组织名。
- 无效成员关系不会出现在组织列。
- 搜索、分页、创建时间排序和平台角色保护保持不变。
- 后端定向测试、前端定向测试、前端构建、桌面端路由检查及 `git diff --check` 通过；没有受权平台会话时，不伪造真实目录验收。

## 风险与回滚

- 一页多组织账户会增加响应体和表格行高，但查询只增加一次批量成员读取，避免 N+1 查询。
- 如出现展示或性能回归，回滚本任务即可去除新增字段与列；不会影响账户或成员数据。

## 交接说明

- 重点路径：`UserRepository`、`PlatformRegisteredUserService`、`PlatformRegisteredUsersPage` 与其定向测试。
- 本任务仅实现和推送功能分支；合并主线与生产发布须由用户另行明确授权。
