# FEAT-092 - 客户互动工作台界面规范化与流式助理

## 背景与目标

生产工作台仍有三类体验缺陷：客户队列工具重复且弹层遮挡内容；CRM 连接状态和若干图标含义模糊；AI 助理在阻塞请求完成前没有过程反馈，并把 Markdown 原文直接显示为井号、竖线和星号。目标是保持现有高保真三栏结构，完成紧凑、明确、可操作的桌面端体验，并让助理从提问开始即显示状态、随后以 SSE 增量输出格式化内容。

## 范围

### In Scope

- 队列工具收敛为一个标准“列表设置”入口，设置区在文档流内展开，不遮挡搜索、筛选或客户行。
- 保留紧凑列表、每页数量和刷新数据三个真实功能；移除无行为的列表密度按钮和仅聚焦搜索框的伪筛选按钮。
- CRM 未连接时显示“CRM 未连接 · 使用演示数据”，并明确演示数据只读、不能写回 CRM；连接时继续显示真实连接状态。
- 移除“打开 CRM 客户主页”、无独立功能的帮助按钮和 AI 标题信息图标。
- 保留并验证通知、复制工作台链接、固定/取消固定、关闭/重新打开助理；全部图标使用 `lucide-react` 公共标准图标库，不保留手绘 SVG 或 CSS 伪元素图标。
- 新增 `POST /customer-workbench/assistant/stream` SSE 接口，事件包含 `workbench`、`phase`、`tool_call`、`delta`、`done`、`error`。
- 前端发送后立即插入用户消息与助理处理中占位；根据阶段显示“正在读取客户上下文/查询 CRM/生成回复”等状态；增量合并 `delta` 并持续滚动到最新内容。
- AI 回复使用现有 `ChatMarkdown` 的 GFM + sanitize 渲染，工作台内补充紧凑标题、段落、列表、引用、代码和表格样式；生成中显示克制的状态动画和流式光标。
- 调整客户助理提示词，要求短段落和项目列表，避免装饰 emoji、超大标题和窄栏不适合的 Markdown 表格。

### Out Of Scope

- 不改变客户队列、指标、建议、CRM 写回和权限数据模型。
- 不新增移动端布局。
- 不创建新的 CloudCC 元数据或页面组件版本；CRM 注入页只复验现有组件加载新前端版本。

## 用户场景

- 销售在队列中打开列表设置，修改密度和每页数量，设置区不覆盖客户列表。
- 未绑定 CRM 的 AgentCiCi 用户能理解当前看到的是演示数据，并知道该状态不能写入 CRM。
- 用户点击通知、复制链接、固定、关闭时得到与图标语义一致的真实行为；不存在装饰性按钮。
- 用户发送文字或语音问题后立即看到助理开始处理，随后文字逐步出现，而不是等待后整块跳出。
- 标题、列表、强调和必要表格按组件渲染，不显示 Markdown 源符号。

## 设计方向

- 用途：面向销售和客户经理的高频企业工作台。
- 语气：紧凑、明确、可信，不增加营销式装饰。
- 视觉：保持暖象牙底、墨色文字、香槟金结构线；标准线性图标统一为 16px，按钮命名通过 `aria-label` 与 `title` 明确。
- 控件：列表设置使用单一 `Settings2` 图标；通知使用 `Bell`；链接使用 `Link2`；固定使用 `Pin/PinOff`；关闭使用 `X`；刷新使用 `RefreshCw`。

## 接口与事件设计

`POST /customer-workbench/assistant/stream` 请求体与原 `/assistant` 一致：

```json
{"accountId":"001...","message":"总结最近互动"}
```

事件契约：

| 事件 | 关键字段 | 前端行为 |
|---|---|---|
| `workbench` | action、actionPayload、uiActions、accountId、sessionId | 缓存白名单页面动作，`done` 后执行 |
| `phase` | phase、modelName | 更新处理中状态，不清除已有流式文字 |
| `tool_call` | toolName | 显示“正在查询业务数据” |
| `delta` | text | 追加到当前助理消息并自动滚底 |
| `done` | ok、runId | 结束生成态并执行页面动作 |
| `error` | message、runId | 保留用户问题，显示可读错误并允许重试 |

旧 `/assistant` 阻塞接口保留兼容，工作台前端切换到流式接口。

## 验收标准

- 桌面端队列设置区无绝对定位遮挡，顶部只保留一个列表设置图标，排序行不存在无行为按钮。
- 页面不存在“打开 CRM 客户主页”、帮助问号和 AI 标题信息图标。
- 所有工作台图标来自 `lucide-react`；无手写 SVG 路径和 CSS 绘制铃铛/问号。
- 通知弹层、复制链接、固定、关闭和重新打开助理均通过真实点击验证。
- 未连接状态文案清楚区分演示数据与 CRM 数据；CRM 嵌入入口仍显示已连接。
- 发送后 150ms 内出现助理处理状态；首个 `delta` 到达后逐段显示；生成期间和结束后消息区位于最新内容。
- Markdown 标题、列表、加粗和表格不以原始 `#`、`|`、`**` 显示，内容不溢出助理栏。
- 后端流事件测试、前端解析/状态测试、Vite build、桌面浏览器、真实 CRM iframe 和生产健康检查通过。

## 风险与回滚

- SSE 中断时将当前消息转为错误态，不执行页面动作；用户可重新发送。
- 保留旧阻塞接口作为短期兼容和回滚路径。
- 发布异常时按生产运行手册回滚前后端镜像，不涉及数据库回滚。

## 实现进展

- 已完成任务授权、SSE 适配、标准图标替换、连接状态澄清、无效入口清理、即时处理状态、Markdown 渲染和自动滚底。
- 浏览器复测发现并修复设置区展开后队列从 6 行变为 7 行但网格未同步的缺陷；展开后客户列表继续占据剩余高度，不再被推到底部。
- 本地 1920x960 真实登录验收：发送后 60ms 出现“正在准备回答”，500ms 显示“相关资料已就绪”；输入框立即清空，长回复结束时消息区距底部为 0；Markdown 已渲染且无原始标题/表格标记，页面无外层滚动，控制台错误为 0。
- 前端 12 个测试文件、56 项测试和 Vite build 通过；后端聚焦测试与编译通过。

- AgentCiCi 与 CloudCC 真实 iframe 均验证发送后 60ms 出现处理状态、输入立即清空、最终距底部为 0；CRM iframe 无平台侧栏/AI 应用按钮，连接身份为 `CCAdmin`。技能 CLI 注入页校验 `issues=[]`。
