# FEAT-207 - 对外售前智能体访客生命周期与线索闭环

## 背景与目标

公开门户中的智能体不是内部销售助手。它只负责产品介绍、需求识别、线索收集和礼貌收口；不能查询客户业务数据，也不能无限对话。访客再次到访时，需要保留可控的销售上下文，但不能把历史完整对话无条件带入新会话。

本功能以本地租户 `org3gxskla32gln3bvop` 的“客服-Mary”为演示对象，能力实现保持租户通用，演示配置只通过正式 API 或管理界面写入，不在源码、迁移或种子数据中固化租户和智能体。

## 范围

### In Scope

- 为 Website 公开渠道建立匿名访客档案和按次访问会话；同一浏览器使用不可逆外部访客标识关联档案。
- 新访问只创建新的聊天会话；原始消息仍按租户保留策略保存，但模型默认不读取上一访问的完整消息。
- 再次来访先展示上一轮结构化摘要，并要求访客选择“继续上次需求”或“开始新咨询”。只有选择继续时才把经服务端裁剪的摘要注入本轮受信上下文。
- 服务端优先识别售中、售后意图并直接终止回答；仅提示登录 CloudCC 后在系统内提交在线工单，不调用客户数据查询工具。
- 售前流程提供产品讲解、需求澄清、联系方式识别、幂等线索落库和完成后礼貌收口。
- 通过服务端状态机限制会话轮次：第 6 个有效访客问题起进入联系方式收集阶段，第 8 个有效访客问题后停止开放式回答；已取得联系方式后立即进入完成态。
- CloudCC 工单入口由后端读取部署配置、校验后返回；前端不维护环境地址或目标域名白名单。
- 为目标租户演示配置 Mary 的公开定位、开场语、Website 渠道和知识范围；公开渠道在服务端强制关闭工具、用户记忆和附件。

### Out Of Scope

- 售中、售后问题的诊断、订单查询、客户资料查询或工单代提交。
- 跨浏览器、跨设备的匿名访客自动合并；需要合并时必须另行设计身份验证。
- 把无限原始对话作为长期记忆注入模型。
- UAT 或生产环境发布。

## 用户场景

1. 首次访客进入门户，Mary 介绍自己可提供售前咨询，围绕产品、场景、规模、时间和预算等必要信息进行有限澄清。
2. 访客留下手机号或邮箱后，服务端幂等创建线索，Mary 告知后续联系并结束本次开放式会话，不再重复索取联系方式。
3. 访客提出实施中、账号、账单、故障、退款等售中售后问题，服务端不把问题交给通用模型或客户查询工具，直接给出 CloudCC 登录和在线工单入口。
4. 同一浏览器再次到访时创建新访问会话；界面显示上一轮简要主题，访客可选择继续或新咨询。新咨询不注入上一轮摘要。
5. 未留下联系方式且连续咨询达到轮次上限时，Mary 提供一次明确的联系方式入口后礼貌收口，避免无限聊天。

## 现状与约束

- Website Token 已包含租户、智能体、外部访客和来源；现有会话键包含页面路径，导致同一访客跨页面产生碎片化上下文。
- 当前 Embed 会话直接复用聊天会话，没有独立访问生命周期、继续/新咨询门禁、线索状态或完成态。
- 当前聊天编排只限制上下文消息条数，不限制访客可持续发送的轮数。
- 公开渠道必须与内部 Agent 工具能力隔离，服务端是意图边界和状态边界的权威。
- 当前 Website 发布配置仍要求 `runAsUserId` 指向有效组织成员。演示租户没有可安全复用的专用 `ORG_USER`，因此本地演示暂保留既有 ACTIVE Owner 作为运行映射，但公开渠道的服务端策略始终为零工具、零用户记忆、零附件；这不构成生产身份验收，生产启用前必须建立专用最小权限成员或支持 SERVICE Principal。

## 方案设计

### 状态模型

- `website_visitor_profile`：租户、智能体、外部访客标识、上次摘要、是否已有线索、当前访问时间等长期最小档案。
- `website_visit_session`：一次访问对应一个新的 `chat_session`，状态为 `AWAITING_CHOICE`、`ACTIVE`、`CONTACT_REQUESTED`、`COMPLETED` 或 `SERVICE_REDIRECTED`。
- `website_presales_lead`：保存经规范化的手机号/邮箱、需求摘要、来源和同意时间；以租户、智能体、访客和联系方式摘要幂等。

### 路由与收口

- Website 消息先经过确定性公开渠道门禁，再进入通用聊天编排。
- 售中售后关键词命中时直接持久化固定引导答复和 `SERVICE_REDIRECTED`，不进入模型、不执行工具。
- 售前消息在进入模型前附加不可被租户提示覆盖的渠道策略：只答产品售前，不索取敏感信息，不承诺价格/交付，不查询客户数据，围绕少量必要问题推进线索。
- 联系方式仅在消息明确包含手机号或邮箱时提取；写入前由 UI 明示“提交即同意用于本次咨询跟进”。取得联系方式后立即 `COMPLETED`。
- 达到第 6 轮但未取得联系方式时，服务端固定要求留下手机号或邮箱；达到第 8 轮仍未取得时固定收口并关闭输入。

### 再访

- 首次访问直接 `ACTIVE`。
- 旧访问已完成、重定向或超过空闲窗口后，再次签发会话时创建新的聊天会话；如果存在非空摘要，则新访问为 `AWAITING_CHOICE`。
- `CONTINUE` 只注入结构化摘要，不复制历史原文；`START_NEW` 清空本轮继承摘要。选择完成前禁止发送自由文本。
- 页面路径只作为来源上下文，不参与匿名访客身份和当前访问唯一性。

## 接口与数据影响

- 数据库新增三个 Website 生命周期表；不改写既有聊天消息和已发布迁移。
- Embed 会话响应增加 `websiteLifecycle`，公开来源才返回。
- 新增访问选择、线索提交/识别和工单入口读取接口；均要求现有 Embed Token，并校验会话与租户绑定。
- 工单入口从 `APP_WEBSITE_PRESALES_CLOUDCC_TICKET_URL` 等部署配置读取，只接受 HTTPS；未配置时仍返回登录系统提交工单的文字，不渲染外链按钮。
- 旧的非 Website Embed、Agent Builder、OpenAPI 和内部对话保持原行为。

## 验收标准

- 首访可完成售前问答；第 6/8 轮门禁、联系方式幂等保存和完成后禁发均有自动化测试。
- 售中售后问题返回固定工单引导，Trace 证明模型调用数和工具调用数均为 0。
- 再访生成不同聊天会话 ID；继续模式只携带结构化摘要，新咨询不携带历史；旧原始消息未删除。
- 已有线索的访客再次来访不重复索取联系方式。
- 工单 URL 只来自后端受校验配置；源码、前端制品和业务测试不含真实环境域名。
- 目标租户 Mary 的定位、欢迎语、发布版本、Website 渠道、零工具/零知识库/零可选技能通过正式产品链路回读；本地运行映射例外和生产专用身份门禁有明确记录。
- 后端聚焦测试与 package、前端聚焦/全量测试与 production build、域名门禁和 `git diff --check` 通过。
- 变更提交进入本地 `main`；backend/frontend 从同一明确提交构建，`https://cici.localhost/`、健康、重启次数、版本和资源指纹回读一致。

## 风险与回滚

- 关键词路由可能误判：仅对明确售中售后表达做确定性拦截，其他消息继续走受约束售前模型；记录分类原因供审计。
- 匿名标识可被清理或伪造：只作为同浏览器便利功能，不视为已验证客户身份，不允许据此查询客户数据。
- 联系方式属于个人信息：最小字段、租户隔离、审计和保留策略必须生效；日志不得输出原值。
- 回滚应用时保留新增表，不回退已执行迁移；关闭 Website 生命周期开关即可恢复旧公开对话行为，历史线索不丢失。
