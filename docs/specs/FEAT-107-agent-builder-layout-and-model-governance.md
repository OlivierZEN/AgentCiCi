# FEAT-107 - 智能体构建页布局与模型治理收敛

## 背景与目标

- 平台已由运营方统一维护可用模型序列、路由、降级与成本策略，Agent 构建者继续选择具体基础模型会形成第二个配置事实源，并让用户误以为运行时一定采用所选模型。
- 当前 Agent 定义页把系统提示词放在左栏底部，把策略、业务定位、兜底规则、基础模型和发布备注放在右栏，两个信息列的语义和高度不平衡。
- “评测”和“发布渠道”属于候选版本从验证到交付的生命周期，不应占用 Agent 基础定义区的一级导航。
- 本次目标是把定义区收敛为稳定的双栏表单，并把评测、渠道与现有编译/版本流程统一到页面下方的生命周期工作区。

## 范围

### In Scope

- Agent 定义页移除用户可见的“基础模型”选择器。
- 保留现有 `draft.model`、保存 payload 和历史 Agent 数据兼容；新 Agent 仍由平台已启用模型序列解析内部默认值，运行时模型路由继续以平台治理配置为准。
- 左栏依次承载 Agent 名称、头像与策略开关、开场白、业务定位、人工兜底规则、发布备注。
- 策略开关与头像操作处于同一视觉行，并保留平衡/严格、协作副驾/自动执行的现有行为。
- 右栏专门承载系统提示词，左右栏顶线、间距和底部高度在桌面端保持整齐。
- 移除定义区顶部“Agent 定义 / 评测 / 发布渠道”页签；Agent 定义始终可见。
- 将“评测”和“发布渠道”加入页面下方“版本控制与交付”页签，与流程预览、触发调度、试运行、版本历史、执行记录和编译产物统一呈现。
- 更新聚焦测试，并完成桌面端浏览器截图和交互检查。

### Out Of Scope

- 不删除后端 Agent 模型字段，不迁移历史数据，不改变运行时模型路由算法。
- 不开放租户或 Agent 级具体模型选择、模型厂商选择或自定义路由。
- 不改变评测 API、发布门禁、渠道配置数据结构或发布动作。
- 不新增移动端布局、移动端截图或移动端自动化测试。
- 不改变“鎏金账房”视觉语言、全局 token 或跨页面组件语汇。

## 用户场景

- 组织管理员编辑 Agent 时，只关注身份、对话入口、业务定位、安全策略、兜底规则和系统提示词，不需要理解平台当前启用了哪个具体模型。
- 构建者在完成定义后，向下进入同一生命周期工作区完成流程检查、试运行、评测、版本追溯和发布渠道配置。
- 当发布就绪检查发现缺少渠道或评测未通过时，界面直接切换到下方对应页签，不再切走 Agent 定义区。
- 平台没有任何可用模型时，新 Agent 创建仍明确提示“请先配置模型”，避免产生不可运行的草稿。

## 现状与约束

- 当前实现位于 `frontend/src/assistant/AgentBuilderShell.tsx` 与 `frontend/src/assistant/cici-ui.css`。
- `draft.model` 参与保存、编译指纹和历史兼容，本次只移除构建者选择入口，不能删除字段。
- FEAT-106 已明确评测与发布渠道语义分离；本次只改变二者在页面中的纵向层级，不重新混合内容。
- 页面是认证后 `product` register，必须沿用暖象牙底、墨色文字、紧凑密度、香槟金结构线和文本 Tab。

## 方案设计

### 模型治理

- 构建页不显示具体模型名或下拉框。
- 新建 Agent 时沿用 `resolveAgentCreationModel`，从平台可用序列得到内部默认模型；没有可用模型时阻止创建并提示平台先完成模型配置。
- 已有 Agent 的模型字段继续原样读取和保存，避免仅因打开页面而改变编译指纹。
- 运行时选择、路由、降级和成本控制仍由平台模型治理能力负责；构建页不再展示模型治理说明，避免右栏出现与编辑任务无关的尾部注释。

### 定义区布局

- 定义区不再有一级页签，标题直接使用“Agent 定义”。
- 双栏使用等宽网格。左栏是短字段和策略，右栏是长文本系统提示词。
- 头像预览/上传/清除与四个策略按钮组成同一行容器，必要时仅在桌面窄宽度内自然换行，不新增移动端专属实现。
- 右栏只承载系统提示词；文本域填满可用高度，使两栏上下边界稳定对齐，不在底部增加说明文字或分隔线。

### 生命周期工作区

- 下方区块标题改为“版本控制与交付”。
- 页签顺序按任务流排列：流程图预览、触发与调度、试运行、评测、版本历史、发布渠道、执行记录、编译摘要、流程代码、Manifest。
- 评测内容继续复用现有生产就绪和评测门禁面板；发布渠道继续复用现有渠道菜单与配置面板。
- 发布就绪引导和数据加载条件统一改为下方页签状态。

## 接口与数据影响

- 无 API、数据库、事件或迁移变化。
- `draft.model` 与现有 Agent 保存请求保持兼容。
- 仅调整前端状态枚举、渲染层级、样式和聚焦测试。

## 任务拆分

- `TASK-201`：完成信息架构、布局、测试与桌面端视觉验收。

## 验收标准

- Agent 定义区不显示“基础模型”标签、下拉框或具体模型名。
- Agent 定义区不显示模型治理说明文字或其分隔线，右栏仅保留系统提示词。
- 头像与策略按钮在同一视觉行；系统提示词位于右栏，业务定位、人工兜底和发布备注位于左栏。
- 桌面端两栏顶线和底部边界整齐，无横向溢出。
- 页面顶部不再显示“评测 / 发布渠道”页签。
- 下方“版本控制与交付”包含独立“评测”和“发布渠道”页签，内容与原行为一致。
- 评测加载、发布就绪引导、渠道启用、保存、编译和发布动作无回归。
- 聚焦 Vitest、前端构建、`git diff --check` 通过；桌面端真实浏览器截图检查通过。

## 风险与回滚

- 风险：移动页签后旧状态跳转仍引用定义区状态，导致评测不加载或发布引导无响应。通过状态引用搜索和聚焦测试覆盖。
- 风险：系统提示词高度过大造成页面首屏过长。使用与左栏内容自然对齐的最小高度，不做固定视口锁定。
- 回滚：恢复原顶层页签与模型下拉即可；无后端和数据迁移，不需要数据回滚。
